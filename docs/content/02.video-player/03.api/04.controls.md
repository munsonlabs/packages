Unstyled primitives for building a custom HUD. Each is published as both a Vue component and an `ml-controls-*` custom element from the same source. Vue components come from the main import; custom elements from `/element` or the smaller `/element/controls`.

```ts
import {
  PlayButton,
  MuteButton,
  FullscreenButton,
  LoopButton,
  PipButton,
  CaptionsButton,
  QualityButton,
  PlaybackRateButton,
  Buffering,
  Scrubber,
  VolumeSlider,
  TimeDisplay,
  Transcript,
} from '@munsonlabs/video-player'
```

| Component            | Custom element                       | Description                                                                                                                                                                                      |
| -------------------- | ------------------------------------ | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| `PlayButton`         | `<ml-controls-play-button>`          | Toggles play/pause                                                                                                                                                                               |
| `MuteButton`         | `<ml-controls-mute-button>`          | Toggles mute                                                                                                                                                                                     |
| `FullscreenButton`   | `<ml-controls-fullscreen-button>`    | Toggles fullscreen                                                                                                                                                                               |
| `LoopButton`         | `<ml-controls-loop-button>`          | Toggles loop                                                                                                                                                                                     |
| `PipButton`          | `<ml-controls-pip-button>`           | Picture-in-Picture - only renders when `supportsPip`                                                                                                                                             |
| `CaptionsButton`     | `<ml-controls-captions-button>`      | Cycles Off → track 1 → … → Off; only when `supportsCaptions`                                                                                                                                     |
| `QualityButton`      | `<ml-controls-quality-button>`       | Cycles Auto → highest → … → Auto; only when `supportsQuality`                                                                                                                                    |
| `PlaybackRateButton` | `<ml-controls-playback-rate-button>` | Cycles `0.5, 0.75, 1, 1.25, 1.5, 2`                                                                                                                                                              |
| `Buffering`          | `<ml-controls-buffering>`            | Renders its content only while `isBuffering`                                                                                                                                                     |
| `Scrubber`           | `<ml-controls-scrubber>`             | Drag-to-seek range input - pauses on drag, previews time, resumes on release                                                                                                                     |
| `VolumeSlider`       | `<ml-controls-volume-slider>`        | Drag-to-set-volume range input with a percentage readout                                                                                                                                         |
| `TimeDisplay`        | `<ml-controls-time-display>`         | `current / total`, or a "Live" badge when `isLive`. Wraps each half in `.mlv-time-display__time` / `__total` for independent styling                                                             |
| `Transcript`         | `<ml-controls-transcript>`           | Clickable transcript from `cues`, with an optional [spoken readout](/video-player/features/transcripts#spoken-readout) of the active cue - [see transcripts](/video-player/features/transcripts) |

## Pointing a control at a player

Via a `player` ref, or `<label for>`-style via an element id:

::tabs
:::tabs-item{label="Vue" icon="i-vscode-icons:file-type-vue"}

```vue
<script setup>
import { ref } from 'vue'
import { VideoPlayer, PlayButton, MuteButton, Scrubber } from '@munsonlabs/video-player'
const player = ref(null)
</script>

<template>
  <VideoPlayer ref="player" src="..." :controls="false" />
  <PlayButton :player="player" />
  <MuteButton :player="player" />
  <Scrubber :player="player" />
</template>
```

Or skip the ref - useful when the control isn't a sibling of the player:

```vue
<VideoPlayer id="my-player" src="..." :controls="false" />
<PlayButton for="my-player" />
```

:::
:::tabs-item{label="Web component" icon="i-vscode-icons:file-type-html"}

```html
<script type="module">
  import '@munsonlabs/video-player/element'
</script>

<ml-video-player id="player" src="..."></ml-video-player>

<ml-controls-play-button for="player"></ml-controls-play-button>
<ml-controls-mute-button for="player"></ml-controls-mute-button>
<ml-controls-scrubber for="player" style="flex: 1"></ml-controls-scrubber>
```

:::
::

::headless-example
::

Both are optional; `player` wins if both are given. `for` resolves through `document.getElementById` - this package never uses shadow DOM, so an id lookup is always correct. `for` is the zero-JS path; the property form (`el.player = ...`) is only needed when the two can't share a stable id, since an object reference isn't expressible as an attribute.

::warning
A bare attribute casts to `true` (`play-in-view`), but `="false"` arrives as the **truthy string** `"false"` - so `controls="false"` on `<ml-video-player>` leaves the built-in HUD on. Set boolean props to false through the property instead: `playerEl.controls = false`.
::

## Scoped slots (Vue only)

Each button exposes its state for fully custom markup - `PlayButton` gives `{ isPlaying }`, `MuteButton` `{ isMuted }`, and so on:

```vue
<PlayButton :player="player" v-slot="{ isPlaying }">
  {{ isPlaying ? 'Pause' : 'Play' }}
</PlayButton>
```

A scoped slot is a render-function callback with no HTML equivalent, so custom elements can't have them. Static children still work as a plain default slot (`<ml-controls-buffering><div class="spinner"></div></ml-controls-buffering>`); for state-reactive markup, toggle your own elements on `state-change`.

## Styling

Every control's CSS uses `:where()` (zero specificity), so one class of yours always wins regardless of source order. In Vue, a class falls through to the control's root element:

```vue
<PlayButton :player="player" class="my-play-btn" />
```

**As a raw custom element it doesn't.** The custom element is a persistent DOM node that Vue renders _into_; a class on the outer tag never reaches the `<button>` inside. Use a descendant selector:

```css
ml-controls-play-button button {
  color: red;
}
/* or the built-in class: */
ml-controls-play-button .mlv-play-button {
  color: red;
}
```

### CSS entry points

| Import            | Pairs with                      | Covers                        |
| ----------------- | ------------------------------- | ----------------------------- |
| `/style`          | `/element`, and plain Vue usage | Core player + all 13 controls |
| `/style/core`     | `/element/core`                 | Just the player components    |
| `/style/controls` | `/element/controls`             | Just the 13 controls          |

Only `/element` auto-injects its CSS. Building a fully custom HUD? `/style/controls` alone is enough - no need to ship the core player's CSS you never render.

### Themeable CSS variables

Set these on any ancestor of the player:

| Variable               | Default                         | Controls                                                                                       |
| ---------------------- | ------------------------------- | ---------------------------------------------------------------------------------------------- |
| `--mlv-max-width`      | `800px`                         | Width cap on the player, its lazy placeholder and the stage - set `none` to fill the container |
| `--mlv-controls-width` | `min(450px, calc(100% - 32px))` | Expanded controls popup width                                                                  |
| `--mlv-popup-align`    | `center`                        | Popup horizontal alignment                                                                     |
| `--mlv-btn-bg`         | frosted glass                   | HUD button background                                                                          |
| `--mlv-btn-color`      | frosted glass                   | HUD button icon/text colour                                                                    |
| `--mlv-stage-tuck`     | `32px`                          | Sliver left visible when `HideMarker` tucks a pinned box away                                  |
| `--mlv-radius`         | `12px`                          | Corner-pinned box border radius                                                                |
| `--mlv-accent`         | —                               | Active-state highlight for the loop and autoplay toggles                                       |

```css
.my-video-wrapper {
  --mlv-btn-bg: #e11d48;
  --mlv-btn-color: #fff;
}
```

Icons use `fill="currentColor"`, so `--mlv-btn-color` recolours them too. Popup show/hide and fullscreen docking are covered on the [behaviour page](/video-player/api/behaviour).

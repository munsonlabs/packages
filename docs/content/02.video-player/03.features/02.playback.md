## Autoplay, mute & volume

Starting mute/volume is decided in one pass, most specific first:

| If…                                                                                                       | Starts at                                            |
| --------------------------------------------------------------------------------------------------------- | ---------------------------------------------------- |
| The video sets `muted` or `volume`                                                                        | That exact value - explicit props always win         |
| Playback starts from a **real gesture** (clicking a lazy placeholder, a stage idle-click, `video-toggle`) | The page's shared audio preference                   |
| Playback starts with **no gesture** (`autoplay`, `playInView` scrolling into view)                        | Muted, always - browser policy, not a library choice |
| A playlist reaches it via **skip / auto-advance**                                                         | The outgoing video's own live mute/volume            |

The **shared preference** is one `localStorage` value per page, not per player: it updates whenever a viewer presses mute or drags a volume slider on _any_ player, so a newly-mounted player starts wherever the viewer last left things instead of resetting to full volume.

The forced-mute rule is scoped to the current page load. Once a real gesture has produced unmuted playback, browsers allow further unmuted programmatic playback, so it stops applying until reload. Playlist skips are the one exception to following the shared preference - they carry the outgoing video's sound forward, so skipping a muted video doesn't turn sound on.

## Scroll-snap feeds (`playInView`)

`playInView` auto-plays once a video is at least half visible and auto-pauses once it isn't. Several visible players share one debounce, so only the last to cross the threshold plays. It works with `VideoCard`'s lazy placeholder, and implies muted unless `muted` is set.

::player-example{src="https://test-streams.mux.dev/x36xhzz/x36xhzz.m3u8" title="Plays in view" play-in-view caption="Scroll this in and out of view - it starts and pauses itself, muted."}
::

The pattern it exists for is a TikTok-style vertical feed - each slide a bare `VideoPlayer` with a HUD built from the [headless controls](/video-player/api/controls):

```vue
<VideoPlayer v-bind="video" :controls="false" :muted="globalMuted" play-in-view @state-change="onStateChange" />

<Buffering :player="playerRef" />
<MuteButton :player="playerRef" />
<PlayButton :player="playerRef" />
<Scrubber :player="playerRef" />
```

## Pinning a single player

`pin` swaps "auto-pause offscreen" for YouTube-style mini-player behaviour: once it scrolls out of view **while playing**, it pins to that corner instead of pausing, with a dismiss button. Like a mini-player, pausing it while pinned doesn't dismiss it.

```vue
<VideoCard src="..." lazy muted pin="bottom-left" />
```

::player-example{src="https://test-streams.mux.dev/x36xhzz/x36xhzz.m3u8" title="Pinned player" muted pin="bottom-left" caption="Press play, then scroll past it - the player pins to the bottom-left instead of pausing."}
::

All four corners are supported. [`HideMarker`](/video-player/api/components#hiding-the-pinned-stage) tucks it away over specific content.

## Sticky stage & playlists

`VideoStage` is a sticky, full-width player that any `VideoCard` on the page hands its video to (over [window events](/video-player/api/components#window-events)), minifying to a corner pip when scrolled past. Pass `playlist` - the same props each card takes - to track position within it:

```vue
<script setup>
import { VideoStage, VideoCard } from '@munsonlabs/video-player'

const videos = [
  { src: 'https://www.youtube.com/watch?v=UnktCDi-BVs', title: 'Oh my gah!' },
  { src: 'https://vimeo.com/347119375', title: 'Tears of Steel' },
]
</script>

<template>
  <VideoStage :playlist="videos" />
  <VideoCard v-for="video in videos" :key="video.src" v-bind="video" />
</template>
```

- **Auto-advance** on `ended` is built in, persisted per browser and toggled from the controls popup's "Auto" button - there's no prop.
- A template ref exposes `playNext()`, `playPrevious()`, `hasNext`, `hasPrevious`.
- Playlist entries take everything a `VideoCard` does - ad tags, `tracks`, poster, `payload`.

## Transcripts

`Transcript` renders a clickable, seekable transcript: clicking a cue seeks to it (starting playback if paused), the cue under the playhead is highlighted and kept scrolled into view, and auto-scroll pauses while your pointer is over the list. It works on **every** platform, embeds included, because it only needs the current time and `seek`:

```vue
<VideoPlayer ref="itemRef" src="..." />
<Transcript
  :player="itemRef"
  :cues="[
    { time: 0, text: 'Opening titles - birds sing over a meadow.' },
    { time: 95, end: 110, text: 'He stops to smell a flower.' },
    { time: 555, text: 'Peace returns to the meadow.' },
  ]"
/>
```

::headless-example
::

`end` is optional - when set, nothing is highlighted between that cue's end and the next cue's start. A scoped slot (`{ cue, index, isActive, formatTime }`) customises each cue's markup; as a custom element, pass `cues` as a JSON string attribute.

### Spoken readout

Where the browser supports the Web Speech API, the transcript also carries a readout toggle that speaks each cue aloud as the playhead reaches it. It mutes the player while enabled so the two don't talk over each other, and restores the sound when switched off - but only if the toggle was what muted it, leaving a mute you set yourself alone. Unmuting from anywhere else (a `MuteButton`, the built-in HUD) switches the readout off rather than competing with now-audible video. The button hides itself entirely where `speechSynthesis` is unavailable.

## Everything else

| Feature              | How it works                                                                                                                                                                                                                         |
| -------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| Fullscreen           | Button or `f`, including iOS native-fullscreen quirks                                                                                                                                                                                |
| Picture-in-Picture   | Button appears where supported; stays in sync with the browser's floating window                                                                                                                                                     |
| Playback rate / loop | Speed cycles `0.5`-`2`, both emit events (`ratechange`, `loopchange`)                                                                                                                                                                |
| Buffering            | Debounced spinner on stall; `bufferstart`/`bufferend` for rebuffer analytics                                                                                                                                                         |
| Live streams         | `TimeDisplay` shows a "Live" badge and seeking is hidden                                                                                                                                                                             |
| Position memory      | Persists and restores playback position across mounts (never for live)                                                                                                                                                               |
| Keyboard shortcuts   | `Space`/`k` play-pause · arrows seek/volume · `m` mute · `f` fullscreen · `c` captions · `0`-`9` percent-jump · `Home`/`End`. Scoped per player, never fire while typing in a text field, and disabled by `disableKeyboardShortcuts` |
| Native UI            | `nativeUi` passes through to YouTube/Vimeo/Dailymotion's own controls instead of the built-in HUD                                                                                                                                    |

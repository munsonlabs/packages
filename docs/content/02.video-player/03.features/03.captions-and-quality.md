Both apply to the native `<video>` path only. YouTube, Vimeo, and Dailymotion draw their own captions inside their iframe and expose no quality override. Brightcove and JW Player get both for free, since they resolve to a real source.

## WebVTT captions (`tracks`)

For sources without their own subtitle renditions - a plain MP4, say - supply WebVTT files. Each entry renders as a native `<track>`; the browser fetches and parses it, and `default: true` shows it immediately:

```vue
<VideoCard
  src="https://cdn.jwplayer.com/videos/O5chtspP-4VHSaSK0.mp4"
  :tracks="[
    { src: '/captions/bbb-en.vtt', kind: 'captions', srclang: 'en', label: 'English', default: true },
    { src: '/captions/bbb-fr.vtt', kind: 'captions', srclang: 'fr', label: 'Français' },
  ]"
/>
```

`<track>` only understands WebVTT - convert SRT and other formats first.

The Captions control cycles Off → first track → … → Off. Programmatically, `setCaptionTrack(index)` selects one and `null` turns captions off; every change fires `captionchange`.

## HLS subtitle renditions

An HLS stream declaring subtitle renditions in its manifest is picked up automatically - by hls.js, or natively in Safari - with **no `tracks` prop**. A Captions option simply appears once the manifest parses:

```vue
<VideoCard src="https://devstreaming-cdn.apple.com/videos/streaming/examples/img_bipbop_adv_example_fmp4/master.m3u8" />
```

## Adaptive quality (HLS / DASH)

Adaptive streams expose a Quality option once the manifest's resolution variants are parsed. It cycles Auto → highest → … → lowest; **Auto leaves the streaming engine's ABR algorithm in control**. `setQuality(index)` selects a level and `null` restores Auto, firing `qualitychange`; levels are `{ index, height, bitrate, label }`.

Plain MP4 has no variants, so no Quality menu.

::callout{type="info"}
Safari plays HLS natively, and native HLS offers no manual quality-override hook - the Quality menu won't appear there, though captions still work.
::

## A fully custom HUD

Set `controls="false"` for a bare `<video>` with no built-in HUD, then build your own from the 13 [headless controls](/video-player/api/controls) - each a Vue component and an `ml-controls-*` custom element - and the [imperative API](/video-player/api/methods) for anything they don't cover:

```vue
<script setup>
import { ref } from 'vue'
import { VideoPlayer, PlayButton, MuteButton, Scrubber } from '@munsonlabs/video-player'

const itemRef = ref(null)
function seekBy(seconds) {
  const { current = 0, total = 0 } = itemRef.value ?? {}
  if (total) itemRef.value.seek(((current + seconds) / total) * 100)
}
</script>

<template>
  <VideoPlayer ref="itemRef" src="..." :controls="false" />

  <PlayButton :player="itemRef" v-slot="{ isPlaying }">{{ isPlaying ? 'Pause' : 'Play' }}</PlayButton>
  <MuteButton :player="itemRef" v-slot="{ isMuted }">{{ isMuted ? 'Unmute' : 'Mute' }}</MuteButton>
  <button @click="seekBy(-10)">« 10s</button>
  <button @click="seekBy(10)">10s »</button>
  <Scrubber :player="itemRef" />
</template>
```

Import `@munsonlabs/video-player/style/controls` instead of the full `/style` to skip CSS for a player HUD you never render.

## Custom actions

`action` adds a button to the built-in HUD - a built-in behaviour or your own:

```vue
<VideoCard action="mute" src="..." />     <!-- also 'loop', 'autoplay' (stage auto-advance) -->
<VideoCard :action="{ icon: '<svg .../>', label: 'Save', onClick: save }" src="..." />
```

## Custom platforms

The platform registry is public, so you can teach the player a source it doesn't ship with. `registerPlatform` is the one call most consumers need - it registers the URL matcher plus whichever of the two adapter kinds applies. Call it once at startup, before any player mounts.

**Source platforms** resolve an opaque URL down to a real file the native path can play - the shortest way to add a platform:

```ts
import { registerPlatform } from '@munsonlabs/video-player'

registerPlatform({
  key: 'mycdn',
  test: (src) => src.startsWith('mycdn://'),
  embed: false,
  resolveSource: async (url) => {
    const { hls, thumbnail } = await fetch(`/api/media/${url.slice(8)}`).then(r => r.json())
    return { src: hls, type: 'application/vnd.apple.mpegurl', poster: thumbnail, adTagUrl: null }
  },
})
```

Everything downstream - captions, quality, PiP, ads, the whole HUD - then works as it does for any direct file. `resolveSource` is optional if the URLs are already directly playable; only the matcher is needed to give them their own platform key.

**Embed platforms** wrap a third-party SDK. `createAdapter` returns a `PlaybackAdapter`: play/pause, time, volume, captions, quality, PiP, and an `on`/`off` emitter the player translates into its own event set.

```ts
registerPlatform({
  key: 'myplatform',
  test: (src) => /myplatform\.com/.test(src),
  embed: true,
  createAdapter: (videoEl, options) => createMyAdapter(videoEl, options),
})
```

| Export | Use |
| --- | --- |
| `registerPlatform(config)` | Matcher + adapter in one call - what you normally want |
| `registerMatcher({ key, test, embed })` | Just the URL-detection rule |
| `registerEmbedAdapter(key, factory)` | Just an embed adapter, for an already-matched key |
| `registerSourceResolver(key, resolver)` | Just a source resolver |
| `getPlatform(url)` | The platform key a URL resolves to, or `'html5'` |

Custom matchers run **after** the five built-ins, so they can't shadow a built-in platform's URLs. `PlatformConfig`, `PlaybackAdapter`, `ResolvedSource`, `Matcher`, `SourceResolver`, and `EmbedAdapterFactory` are all exported as types.

## Composables

The logic behind the built-in controls is exported, so a custom control can reuse it rather than reimplement it:

| Composable | Returns |
| --- | --- |
| `useScrubber(playerRef)` | `{ scrubbing, displayPercent, previewSeconds, onInput, onChange, onTouchEnd }` - the full pause-on-drag, preview, commit-on-release dance |
| `useCaptions(player)` | `{ cycleCaptionTrack, currentCaptionLabel }` |
| `useQuality(player)` | `{ cycleQuality, currentQualityLabel }` |
| `usePlaybackRate(player)` | `{ cycleRate, fmtRate }` |

## Wrapping and exposing a player

- [`useForwardedPlayer`](/video-player/api/methods#useforwardedplayer) forwards a wrapped `VideoPlayer`'s full handle through your own component's `defineExpose`, with an optional `guard` to intercept calls.
- [`exposePlayerOnElement`](/video-player/api/methods#exposeplayeronelement) copies that handle onto a DOM element, so a third party's script or a separately-bundled `<ml-controls-*>` element can drive a plain Vue player.

## Theming

Override the [CSS variables](/video-player/api/controls#themeable-css-variables) on any ancestor of the player - popup width and alignment, button colours, corner radius, accent:

```css
.my-video-wrapper {
  --mlv-btn-bg: #e11d48;
  --mlv-btn-color: #fff;
  --mlv-controls-width: min(600px, calc(100% - 32px));
}
```

Every control's own CSS uses `:where()` (zero specificity), so a single class of yours always wins - no `!important`, no forking. Outside fullscreen the controls bar opens on "show controls" and stays until dismissed; in fullscreen it auto-shows on activity and hides after inactivity.

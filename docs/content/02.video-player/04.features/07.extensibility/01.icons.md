Every icon the HUD and controls draw is resolved by name through [`@munsonlabs/sigil`](/sigil/getting-started/introduction), registered as the `mlv` library, and pinned there with `library="mlv"` - so sigil's `use()` never reaches it, and a page that uses sigil for its own icons can't blank the player's controls by accident.

`override` replaces one icon; registering your own `mlv` library replaces the whole set, before or after the player loads, from anywhere on the page - registering under an existing name replaces it, so every mounted player follows with no rebuild. A replacement set must answer every name in the table below; there is no fallback to the built-in icons for names it lacks. `unregister('mlv')` puts the built-in set back.

```ts
import { override, register } from '@munsonlabs/sigil'

// one icon
override('mlv-play', '<svg viewBox="0 0 24 24" fill="currentColor"><path d="…"/></svg>')

// the whole set, from your own SVGs or a CDN
register('mlv', {
  resolver: (name) => `https://cdn.example.com/player-icons/${name.replace('mlv-', '')}.svg`,
})
```

| Name                                          | Where it appears                          |
| --------------------------------------------- | ----------------------------------------- |
| `mlv-play`, `mlv-pause`, `mlv-replay`         | Play/pause button, ended and error states |
| `mlv-volume-on`, `mlv-volume-mute`            | Mute button, volume panel, ad overlay     |
| `mlv-fullscreen-enter`, `mlv-fullscreen-exit` | Fullscreen button                         |
| `mlv-captions`, `mlv-quality`, `mlv-loop`     | Controls popup                            |
| `mlv-pip`, `mlv-skip-next`, `mlv-more`        | Controls popup, stage                     |
| `mlv-controls`, `mlv-expand`, `mlv-close`     | HUD "show controls", pinned stage         |
| `mlv-back`                                    | Popup sub-menus                           |

The npm build lists `@munsonlabs/sigil` as a dependency, so your bundler dedupes it with your own imports. The web-component bundles carry their own copy, keeping their bare imports to `vue`, `hls.js` and `dashjs`; a script that imports `@munsonlabs/sigil` from anywhere still reaches the same registry, because the shared instance lives on `globalThis`.

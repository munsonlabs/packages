title: Resolution
description: How a name becomes an icon.
navigation:
  icon: i-lucide:route
---

1. **A library-scoped override** (`override(name, icon, { library })`) for that exact name wins, if the query resolves to that library.
2. Otherwise **a global override** for that exact name wins.
3. Otherwise **one library** is asked: `library` if the tag names one, else the default set by `use()`, else the only library if there is exactly one.

Nothing else is tried. With several libraries and no default, name one or call `use()`.

::icon-example{names="heart,heart@lucide,heart@glyphs"}
::

## Variants

`variant` is a free string for state, e.g. `variant="active"`. It reaches the library's resolver alongside the name.

::icon-variant-example
::

## Sync first

Overrides, fonts and cached SVGs paint immediately. Only an uncached SVG fetches. While it does, the element keeps its previous content, or stays empty on first render - style `ml-sigil-icon:empty` if you want a box.

## Live updates

Every `register`, `override`, `unregister` and `use` re-renders every mounted icon. That is how a script loaded after the page can swap icons in place.

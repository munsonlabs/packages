`@munsonlabs/loom` turns a JSON **definition** into a Vue widget. The definition is a tree of blocks (text, images, buttons, stacks) whose props bind to values and actions your app provides.

```vue
<Widget :kit="kit" :definition="productCard" :data="product" :context="{ cart }" />
```

Loom knows nothing about your data. A story feed, a product catalogue, match scores: you plug in what your widgets can read and do as a **kit**, and loom renders definitions against it.

## The pieces

| Piece          | What it is                                                                                                 |
| -------------- | ---------------------------------------------------------------------------------------------------------- |
| **Definition** | JSON: a tree of blocks and the CSS variables it sets. The whole widget.                                    |
| **Kit**        | What your app plugs in: sources, extra blocks, kinds. Made once with `createKit()`.                        |
| **Source**     | A named set of values and actions a definition can bind to, usually one of your composables.               |
| **Block**      | Something to render. Fifteen are built in; a kit can add its own.                                          |
| **Kind**       | A kind of data (an article, an event, a product) and the definition a new widget of that kind starts from. |

## Why data, not code

- **Safe to hand out.** A definition can only bind to fields your kit declares. There's nothing to execute and nothing to sanitise, so clients can build their own widgets.
- **No deploy.** A definition is a JSON document. Store it, fetch it, swap it at runtime.
- **Checkable.** `validateDefinition()` reports every binding that doesn't fit, before anything renders.
- **Your logic stays yours.** Sources wrap the composables you already have. Loom calls them; it never reimplements them.

## Watch it being built

`apps/demos/loom-steps` is a small app with one chapter per commit of loom's history: what that step added and why, the files to read, and a live example. Check out any commit and run it to see loom as it was then.

```bash
vp run --filter loom-steps-demo dev   # http://localhost:5214
```

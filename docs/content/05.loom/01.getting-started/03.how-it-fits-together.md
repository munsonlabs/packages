## Loom in one minute

A widget is usually a Vue component someone writes and ships. With loom, a widget is **data**: a JSON file that says "a stack with an image, a headline bound to the story's title, and a Save button that calls the app's save action". Loom reads that JSON and renders it.

That splits a widget into three parts owned by different people:

![Designers own the JSON, app developers own the kit, and loom renders the two together into a card](/loom/who-owns-what.svg)

| Part                                                    | Who owns it        | Where it lives                                   |
| ------------------------------------------------------- | ------------------ | ------------------------------------------------ |
| **What it looks like**: layout, text, colours, variants | Designers, editors | JSON, edited in Loom Studio, published as a file |
| **What it can show and do**: data and actions           | App developers     | A **kit** of composables, in the app's code      |
| **How it renders**: blocks, bindings, themes, variants  | Loom               | `@munsonlabs/loom`                               |

The payoff: a new card design or a variant for narrow screens is a JSON change, published without an app release, and it can only use what the kit allows.

### The words

- **Definition**: one widget's JSON. A tree of **blocks** (Stack, Text, Image, Button…), each with props, plus the **conditions** that say which data it's for and the sources it **uses**.
- **Binding**: a prop fed from data, as `"story.title"`, or a click wired to an action, as `"actions.toggleSave"`.
- **Kit**: what an app plugs into loom. Its **sources** (composables that provide values and actions), extra blocks, themes, and a **guard** that sees every action first.
- **Context**: what sources get to talk to the app. In Bolt, the native bridge.
- **Variant**: a set of changes to a widget, picked by a **rule** on the data, the width or the colour scheme. "Compact" when narrow, "Subscribers only" when locked.
- **Library**: every widget for a kit in one JSON file. What an app loads.

### What happens when a card renders

![A library is loaded, a widget is picked by its conditions, then a variant, sources are set up and blocks rendered; a tap goes through the kit's guard to the action and on to the app](/loom/render-flow.svg)

## The packages

These are what an app installs.

| Package                                                | What it does                                                                                                                                                                                                                                           |
| ------------------------------------------------------ | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| **`@munsonlabs/loom`** (`packages/loom`)               | The renderer and everything about definitions: `<Widget>`, `createKit`, the fifteen built-in blocks, design tokens and themes, variants and rules, validation, libraries. Knows nothing about any app's data.                                          |
| **`@munsonlabs/loom-studio`** (`packages/loom-studio`) | The editor, a Vue component (`<LoomStudio>`, built on Nuxt UI). Click any part of a widget to edit it, bind it to the kit's sources, design variants, try it for real, export or import JSON. An app embeds it in its own admin page with its own kit. |
| `@munsonlabs/video-player`                             | The player behind loom's optional `Video` block (`@munsonlabs/loom/video`).                                                                                                                                                                            |
| `@munsonlabs/sigil`                                    | The icon registry behind loom's optional `Icon` block (`@munsonlabs/loom/icon`).                                                                                                                                                                       |
| `@munsonlabs/shipkit`                                  | Shared build, lint and test config for every package. Not used at runtime.                                                                                                                                                                             |

## The demos

These show loom used the way a Bolt app would. Nothing in them is published; they're examples to read and run.

| Demo                                                    | What it is                                                                                                                                                                                                                                            |
| ------------------------------------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| **`timeline-kit`** (`apps/demos/timeline-kit`)          | **The app's half**: Bolt's story timeline as a kit. One file per composable (`sources/`), one JSON file per example widget (`widgets/`), the themes, the paywall guard, and sample stories. Both demos below use it. Not an app itself.               |
| **`bolt-bridge-stub`** (`apps/demos/bolt-bridge-stub`)  | **The phone's half**: a small copy of `@pugpigbolt/bridge`, plus a pretend native app. It holds saved, read, playing and subscribed state, and talks to the web the way Bolt's shell does. It's the kit's context. Not an app itself.                 |
| **`loom-studio`** (`apps/demos/loom-studio`, port 5189) | **The editing side**: Loom Studio on the timeline kit. Edit the example widgets, preview them on sample stories, try their actions against the stub bridge, flip **Subscriber** to see locked stories. **Publish** downloads `timeline.library.json`. |
| **`loom-feed`** (`apps/demos/loom-feed`, port 5195)     | **The app side**: a timeline that only consumes. It renders the stories from the bridge with a library: its bundled one, or one you import from the studio. No editor. Its **Bridge** panel shows every message between web and app.                  |
| **`loom-steps`** (`apps/demos/loom-steps`, port 5214)   | **The history**: one chapter per commit of loom's build, each with what changed, the files to read and a live example. Its later chapters use the kit, the stub and the studio.                                                                       |

How they relate:

![The studio and the feed both use the timeline kit and talk to the app through the bridge stub; the studio publishes a library file the feed imports](/loom/demos.svg)

`loom-steps` stands beside them: it uses loom, and from its later chapters the timeline kit, the bridge stub and the studio, to show each step of the build. Nothing depends on it.

What one tap does, through the bridge. The web asks the app, the app says something changed, and the web reads the new state:

## File by file

One sentence per file, for the packages you'll work in.

### `packages/loom/src`

Each folder has its own README in the repo with more detail.

| File                      | What it does                                                                                                                              |
| ------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------- |
| `index.js`                | Lists everything the package exports.                                                                                                     |
| `Widget.vue`              | The `<Widget>` component: picks the definition and variant, themes the root, and hands the tree to `WidgetNode`.                          |
| `WidgetNode.vue`          | Draws one node (its `if`, its props, its block) and, through itself, its children.                                                        |
| `renderer.js`             | What a widget's nodes share: the sources it sets up, reading a binding, and sending every tap through the kit's guard.                    |
| `types/definition.js`     | The shape of a widget's JSON: nodes, bindings, variants, their rules and overrides.                                                       |
| `types/blocks.js`         | The shape of a block: its props, their defaults, and what they can be bound to.                                                           |
| `types/kit.js`            | The shape of a kit: sources, blocks, themes.                                                                                              |
| `types/guard.js`          | The shape of a kit's guard, which sees every action.                                                                                      |
| `kit/createKit.js`        | `createKit`: checks and builds a kit from an app's sources, blocks, themes and guard.                                                     |
| `kit/provide.js`          | `provideKit`: shares a kit and its context with every widget below a component.                                                           |
| `kit/lookup.js`           | Finds things in a kit: a theme, a block's defaults.                                                                                       |
| `blocks/builtin/`         | The 15 built-in blocks, one SFC each (`Text.vue`, `Stack.vue`, …): the props it takes and their defaults, the HTML it draws, and its CSS. |
| `blocks/video/`           | The optional `Video` block, built on `@munsonlabs/video-player`.                                                                          |
| `blocks/icon/`            | The optional `Icon` block, built on `@munsonlabs/sigil`.                                                                                  |
| `definitions/paths.js`    | Reads a binding like `story.title`, and lists what a node is allowed to bind to.                                                          |
| `definitions/match.js`    | Picks the widget for some data: the first whose conditions hold.                                                                          |
| `definitions/variants.js` | Checks variant rules to pick one, and applies a variant's changes on top of the base.                                                     |
| `definitions/validate.js` | Checks a definition against a kit and lists every problem, from unknown blocks to colours that won't follow dark mode.                    |
| `definitions/library.js`  | Packs every widget for a kit into one library file, and loads one back, skipping what can't render.                                       |
| `theme/tokens.js`         | The design tokens (colours, spacing, type, radii, shadows) and the built-in light and dark themes.                                        |
| `theme/scheme.js`         | Works out light or dark mode, following the device, and swaps a theme for its dark partner.                                               |
| `theme/lightDark.js`      | Reads and writes CSS `light-dark()` values, for a colour that differs between light and dark.                                             |
| `theme/styles.css`        | The default value of every token, and the CSS several blocks share.                                                                       |

## Where to change what

| You want to…                                               | Change                                                             |
| ---------------------------------------------------------- | ------------------------------------------------------------------ |
| Change how a widget looks, or add a variant                | Its JSON, in the studio, or `timeline-kit/src/widgets/*.json`      |
| Give widgets a new value or action                         | A composable and its source in `timeline-kit/src/sources/`         |
| Support a new kind of story                                | An example widget in `timeline-kit/src/widgets/`, with its `match` |
| Change what locked stories do                              | `timeline-kit/src/paywall.js`                                      |
| Change how the web talks to the app                        | `bolt-bridge-stub/src/` (in Bolt, `@pugpigbolt/bridge`)            |
| Add a block, or change how blocks, variants or themes work | `packages/loom/src/blocks/`, `definitions/` or `theme/`            |
| Change the editor                                          | `packages/loom-studio`                                             |

## Running it

```bash
vp run --filter loom-studio-demo dev   # http://localhost:5189
vp run --filter loom-feed-demo dev     # http://localhost:5195
vp run --filter loom-steps-demo dev    # http://localhost:5214
```

In the studio, edit a widget and **Publish**. In the feed, **Import** the downloaded file.

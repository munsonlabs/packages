```json
{
  "version": 2,
  "id": "product-card",
  "name": "Product card",
  "match": [{ "path": "kind", "op": "equals", "value": "product" }],
  "uses": ["product"],
  "vars": { "--w-accent": "#4f46e5", "--w-radius": "14px" },
  "root": {
    "id": "card",
    "type": "Stack",
    "children": [
      { "id": "name", "type": "Text", "props": { "variant": "subtitle" }, "bind": { "text": "product.name" } },
      { "id": "price", "type": "Text", "bind": { "text": "product.price" } },
      { "id": "add", "type": "Button", "props": { "label": "Add" }, "on": { "click": "product.add" }, "if": "!product.soldOut" }
    ]
  },
  "variants": []
}
```

`match` says which data the widget is for, and `uses` which sources it binds to: see [Matching](/loom/core-concepts/matching).

## Nodes

Every node has an `id` (unique in the tree, stable: variants refer to it) and a block `type`. The rest is optional:

| Field      | Does                                                                                            |
| ---------- | ----------------------------------------------------------------------------------------------- |
| `props`    | Static values: `{ "variant": "title", "lines": 2 }`.                                            |
| `bind`     | Props from data: `{ "text": "product.name" }`. Wins over a static value for the same prop.      |
| `on`       | Events to actions: `{ "click": "product.add" }`, or `{ "action": "shop.open", "arg": "item" }`. |
| `if`       | Render only when a value is truthy: `"product.inStock"`. `!` negates: `"!product.soldOut"`.     |
| `style`    | Inline CSS: `{ "padding": "var(--w-padding)" }`.                                                |
| `children` | For containers: `Stack` and `Repeat`.                                                           |

## Value paths

A value path is `source.field`, optionally with a deeper path: `product.name`, `item.entry.title`. Sources come from the [kit](/loom/core-concepts/kits-and-sources); inside a `Repeat`, `item` is the current item and `repeat` its position (`repeat.number`, `repeat.last`…, see [Repeating](/loom/core-concepts/blocks#repeating)). Value paths are type-checked against the fields sources declare: a `boolean` can't fill a `Text`, a value can't be clicked. A bound value that's missing renders nothing, never the prop's default.

Actions with no `arg` are called with no arguments, never with the DOM event. A node that runs a click stops it reaching clickable ancestors, so a button inside a tappable card only does its own thing.

## Theme

`vars` are CSS variable overrides for this widget (`{ "--w-gap": "12px" }`), set on its root. Every block reads `--w-*` variables, so a widget is restyled by its variables, and a variant can change them.

## Checking

```js
validateDefinition(kit, definition) // → [] when it renders as written
```

Each issue names its node and, for variant-only problems, its variant.

A kit is everything your app lets widgets use: its data and actions, its blocks, its kinds of data, and its themes.

```js
const kit = createKit({ sources, blocks, kinds, themes, describe })
```

| Option     | Is                                                                                                                         |
| ---------- | -------------------------------------------------------------------------------------------------------------------------- |
| `sources`  | What definitions can bind to.                                                                                              |
| `blocks`   | Blocks beyond the fifteen built-ins. See [Blocks](/loom/core-concepts/blocks#your-own).                                    |
| `kinds`    | The [kinds of data](/loom/core-concepts/kinds) widgets are made for.                                                       |
| `describe` | A short label for a piece of data, for sample pickers and logs.                                                            |
| `themes`   | Token values widgets start from; the first is the default. See [Tokens and themes](/loom/core-concepts/tokens-and-themes). |

Kits are values, not global registries: two apps (or a timeline and a shop) can each have their own on one page.

## Data and context

Every widget renders one piece of **data**: whatever your sources read. **Context** is whatever they need from the app: a native bridge, a cart, a router. Pass both to `<Widget>`, or provide them once:

```js
provideKit(kit, context)
```

## Sources

```js
defineSource({
  id: 'event',
  label: 'Event',
  description: "An event's date and calendar actions.",
  fields: {
    date: { type: 'string', description: 'Start date, localised' },
    hasCorrectDates: { type: 'boolean' },
    addToCalendar: { type: 'action' },
  },
  setup: ({ data, index, context }) =>
    useEvent(
      {
        get story() {
          return data
        },
        get index() {
          return index
        },
      },
      context,
    ),
})
```

- **`fields`** declare what the source returns, typed `string`, `number`, `boolean`, `list`, `object` or `action`. Editors offer them; the validator checks against them.
- **`setup`** runs once per rendered widget, the first time a binding reaches the source, inside the widget's effect scope. Return refs, computeds and functions: loom unwraps refs as it reads.
- **`data`, `index` and `context` are getters.** Read them inside your `computed`s and they stay reactive; that's why the example passes `{ get story() { return data } }` rather than `{ story: data }`.
- **`primary: true`** lists a source first in editors. Use it for the data's own fields.

`setup` is where your composables plug in unchanged. Shape the arguments they expect, call them, return the result.

## Lists

A `list` field can describe its items, so a `Repeat` bound to it offers their fields as `item.*`:

```js
children: { type: 'list', item: { '': 'object', 'entry.title': 'string', read: 'boolean' } }
```

`''` is the item itself, for passing it to an action: `{ "action": "openArticle.openArticle", "arg": "item" }`.

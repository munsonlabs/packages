A kind is a sort of data your widgets are made for, an article, an event, a product, and where a new widget of that kind starts.

```js
defineKind({
  id: 'event',
  label: 'Event',
  icon: 'i-lucide-calendar',
  matches: (story) => story.entry.type === 'event',
  sources: ['event'], // listed first in the studio
  starter: () => eventCard, // without its id, name and kind
})
```

Each definition records the kind it's for: `"kind": "event"`.

## Picking a widget for the data

```vue
<Widget :kit="kit" :definitions="published" :data="story">
  <template #fallback="{ data }">Nothing for this one</template>
</Widget>
```

With `definitions`, the widget uses the first definition whose kind `matches` the data. When none does, the `fallback` slot renders, or nothing. The same lookup is `matchDefinition(kit, data, definitions)`.

| Different…                    | Use                                       |
| ----------------------------- | ----------------------------------------- |
| data shape or actions         | a kind                                    |
| presentation of the same data | a [variant](/loom/core-concepts/variants) |

## Starting a widget

```js
createDefinition(kit, 'event', { id: 'gig', name: 'Gig' })
```

copies the kind's starter with the identity given.

An app doesn't load widgets one by one. It loads a **library**: every definition for a kit, in one JSON file, in the order `<Widget :definitions>` tries them.

```json
{
  "format": "loom-library",
  "version": 1,
  "kit": "timeline",
  "publishedAt": "2026-10-10T09:00:00.000Z",
  "sources": ["event", "story", "video"],
  "blocks": ["Image", "Stack", "Text", "Video"],
  "kinds": [{ "id": "breaking", "label": "Breaking", "extends": "article", … }],
  "widgets": [{ "version": 2, "id": "article-card", … }, { "version": 2, "id": "event-card", … }]
}
```

`sources` and `blocks` list everything the widgets need, so an app can tell what it's missing before it renders anything. `kit` is the kit's `id`, set with `createKit({ id: 'timeline', … })`; it's left out when the kit has none. `kinds` are [kinds made in an editor](/loom/core-concepts/kinds#kinds-made-in-an-editor), left out when there are none.

## Publishing

```js
import { createLibrary } from '@munsonlabs/loom'

const library = createLibrary(kit, definitions, {
  publishedAt: new Date(),
  kinds,
})
await save('timeline.library.json', JSON.stringify(library))
```

Order matters between widgets of equally specific kinds: the first whose kind matches an item renders it. A widget for a kind that [narrows](/loom/core-concepts/kinds#narrowing-a-kind) another wins over the broader one wherever it sits. A second widget of the same kind is never picked, so the studio warns about it: narrow its kind, use a [variant](/loom/core-concepts/variants), or move it first to make it the live one.

## Loading

```js
import { loadLibrary } from '@munsonlabs/loom'

const { kit: libraryKit, widgets, skipped, missing, kitMismatch } = loadLibrary(kit, await fetch('/timeline.library.json').then((r) => r.text()))
```

```vue
<Widget v-for="item in feed" :key="item.id" :kit="libraryKit" :definitions="widgets" :data="item" />
```

`loadLibrary` takes the JSON text, the parsed object, or a bare array of definitions. It adds the library's kinds to this kit (in place of any it had from an editor), then validates each widget against the result:

| Field          | Is                                                                                                                                                                                       |
| -------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `kit`          | This kit with the library's kinds added. Render with it: some widgets may be for those kinds.                                                                                            |
| `kinds`        | The library's kinds that loaded.                                                                                                                                                         |
| `skippedKinds` | `{ id, issues }` for each kind that doesn't fit this kit, such as one extending a kind it doesn't have. Widgets of those kinds are skipped too.                                          |
| `widgets`      | The definitions that render here, in order. Warnings (a colour that won't follow dark mode) don't stop one loading.                                                                      |
| `skipped`      | `{ id, name, issues }` for each widget with errors, such as a block or source this kit doesn't have, or an entry that isn't a definition at all. An older app skips them and carries on. |
| `missing`      | `{ sources, blocks }` the library needs and this kit lacks.                                                                                                                              |
| `kitMismatch`  | `{ expected, actual }` when the library was made for another kit id.                                                                                                                     |
| `publishedAt`  | When it was made, if it says.                                                                                                                                                            |

It throws a `LibraryError` for something that isn't a library at all, an unknown `format`, or a newer `version` than this loom reads.

## In the studio

**Export** has a **Whole library** tab when you pass `:library` to `LoomStudio`; it downloads `<kit id>.library.json`. **Import** accepts a library or a single definition: a library comes back through `@import-library` with the `loadLibrary` result. See [Loom Studio](/loom/studio/loom-studio#export-and-import).

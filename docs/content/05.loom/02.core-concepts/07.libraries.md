An app doesn't load widgets one by one. It loads a **library**: every definition for a kit, in one JSON file, in the order `<Widget :definitions>` tries them.

```json
{
  "format": "loom-library",
  "version": 1,
  "kit": "timeline",
  "publishedAt": "2026-10-10T09:00:00.000Z",
  "sources": ["event", "story", "video"],
  "blocks": ["Image", "Stack", "Text", "Video"],
  "widgets": [{ "version": 2, "id": "article-card", … }, { "version": 2, "id": "event-card", … }]
}
```

`sources` and `blocks` list everything the widgets need, so an app can tell what it's missing before it renders anything. `kit` is the kit's `id`, set with `createKit({ id: 'timeline', … })`; it's left out when the kit has none.

## Publishing

```js
import { createLibrary } from '@munsonlabs/loom'

const library = createLibrary(kit, definitions, { publishedAt: new Date() })
await save('timeline.library.json', JSON.stringify(library))
```

Order matters: an item gets the first widget whose [conditions](/loom/core-concepts/matching) it meets, so put narrower widgets before broader ones.

## Loading

```js
import { loadLibrary } from '@munsonlabs/loom'

const { widgets, skipped, missing, kitMismatch } = loadLibrary(kit, await fetch('/timeline.library.json').then((r) => r.text()))
```

```vue
<Widget v-for="item in feed" :key="item.id" :definitions="widgets" :data="item" />
```

`loadLibrary` takes the JSON text, the parsed object, or a bare array of definitions. It validates each one against this kit:

| Field         | Is                                                                                                                                           |
| ------------- | -------------------------------------------------------------------------------------------------------------------------------------------- |
| `widgets`     | The definitions that render here, in order. Warnings (a colour that won't follow dark mode) don't stop one loading.                          |
| `skipped`     | `{ id, name, issues }` for each widget with errors, such as a block or source this kit doesn't have. An older app skips them and carries on. |
| `missing`     | `{ sources, blocks }` the library needs and this kit lacks.                                                                                  |
| `kitMismatch` | `{ expected, actual }` when the library was made for another kit id.                                                                         |
| `publishedAt` | When it was made, if it says.                                                                                                                |

It throws a `LibraryError` for something that isn't a library at all, an unknown `format`, or a newer `version` than this loom reads.

```vue
<LoomStudio v-model="definition" :kit="kit" :samples="items" :context="context" @publish="save">
  <template #actions><!-- your own controls, top left --></template>
</LoomStudio>
```

| Prop      | Is                                                                                       |
| --------- | ---------------------------------------------------------------------------------------- |
| `v-model` | The definition being edited. Every change is a new object, so it's easy to save or diff. |
| `kit`     | The same kit you render with.                                                            |
| `samples` | Data to preview with. The ones the widget matches are offered.                           |
| `context` | What sources get in the preview.                                                         |

Emits `publish(definition)`.

## Canvas first

The widget sits centred on a faintly dotted canvas, labelled with its width, size bucket, theme and variant. There are no sidebars: everything opens where you're working.

- **Click any element** and its editor opens beside it: a breadcrumb up to its containers, the actions (add, move, nest, duplicate, delete), and four tabs:
  - **Content**: each prop, static or bound. The bind menu lists every field of every source, grouped, filtered to the types that fit.
  - **Actions**: what clicking runs, and the argument it gets.
  - **Show when**: a value that must be truthy.
  - **Style**: inline CSS.
- An element that isn't on screen (switched off by its _Show when_) opens against its nearest visible container, outlined dashed, with a note saying why.
- **Bottom bar**: the variant you're editing, the sample data, the width (narrow, phone, tablet, full), and **Rules** to let variants pick themselves as in production.
- **Top right**: undo and redo, the theme, issues (click one to jump to it), export, publish. Errors block publishing.
- **Theme**: every token, grouped (colour, roles, type, space, shape), showing what the kit's theme gives and marking what this widget overrides, each with a reset. Variants get the same panel for their own overrides. With more than one theme in the kit, the bottom bar previews each.
- **Values pick from tokens**: a Stack's gap, a style's padding, radius, colour or font size offer the theme's scales first, with a custom value always available.

| Keys      | Does                            |
| --------- | ------------------------------- |
| ⌘Z / ⇧⌘Z  | Undo / redo                     |
| ⌘D        | Duplicate                       |
| ⌘↑ / ⌘↓   | Move among siblings             |
| Backspace | Delete (hide, in a variant)     |
| Esc       | Close the editor, then deselect |

## Editing a variant

Pick a variant in the bottom bar and every change becomes an override: fields you change get a marker that resets them to the base, moves become the variant's order, and delete hides. Adding and nesting stay on the base, so variants never drift apart in structure. Hidden elements are listed in the variant menu to bring back.

## Export and import

**Export** has two tabs: **This widget** (its definition) and **Usage** (the code that loads it). Copy or download the JSON.

**Import** takes a pasted definition, which replaces the widget you're editing.

See [Installation](/loom/getting-started/installation#3-edit-widgets): the host app installs Nuxt UI and scans `@munsonlabs/loom-studio`.

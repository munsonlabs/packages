```vue
<LoomStudio v-model="definition" :kit="kit" :samples="items" :context="context" @publish="save">
  <template #actions><!-- your own controls, top left --></template>
</LoomStudio>
```

| Prop      | Is                                                                                       |
| --------- | ---------------------------------------------------------------------------------------- |
| `v-model` | The definition being edited. Every change is a new object, so it's easy to save or diff. |
| `kit`     | The same kit you render with.                                                            |
| `samples` | Data to preview with. The ones the widget matches are offered.                           |
| `context` | What sources get in the preview. Every function called on it is logged.                  |

Emits `publish(definition)`.

## Canvas first

The widget sits centred on a faintly dotted canvas, labelled with its width, size bucket, theme and variant. There are no sidebars: everything opens where you're working.

- **Click any element** and its editor opens beside it: a breadcrumb up to its containers, the actions (add, move, nest, duplicate, delete), and four tabs:
  - **Content**: each prop, static or bound. The bind menu lists every field of every source, grouped, filtered to the types that fit.
  - **Actions**: what clicking runs, and the argument it gets.
  - **Show when**: a value that must be truthy.
  - **Style**: inline CSS.
- **Drag any element** to move it: a line shows where it lands before or after its neighbours, a box when it drops into a container. Drags start after a few pixels, so a click still selects.
- **⌘K** jumps to any element, adds a block, switches variant, or opens any panel. An element that isn't on screen (hidden in this variant, or switched off by its _Show when_) opens against its nearest visible container, outlined dashed, with a note saying why and, for hidden ones, a **Show** button.
- **Bottom bar**: the variant you're editing, the sample data, the width (narrow, phone, tablet, full), **Rules** to let variants pick themselves as in production, and **Try** to use the widget for real.
- **Top right**: the studio's own light or dark appearance, undo and redo, the theme, issues (click one to jump to it), export, publish. Errors block publishing; warnings (a colour that won't follow dark mode) don't, and one click marks the widget's colours as deliberate.
- **Light and dark**: the sun and moon in the bottom bar preview the widget in either scheme, or follow the device, switching to the theme's dark counterpart. Any colour field (in Style, a Box, the theme panel) has a moon: press it to give that colour its own dark value. The theme panel reads light first, with each colour's dark value beside it.
- **Theme**: every token, grouped (colour, roles, type, space, shape), showing what the kit's theme gives and marking what this widget overrides, each with a reset. Variants get the same panel for their own overrides. With more than one theme in the kit, the bottom bar previews each.
- **Values pick from tokens**: a Stack's gap, a style's padding, radius, colour or font size offer the theme's scales first, with a custom value always available.

| Keys      | Does                            |
| --------- | ------------------------------- |
| ⌘K        | Everything                      |
| ⌘Z / ⇧⌘Z  | Undo / redo                     |
| ⌘D        | Duplicate                       |
| ⌘↑ / ⌘↓   | Move among siblings             |
| Backspace | Delete (hide, in a variant)     |
| Esc       | Close the editor, then deselect |

## Editing a variant

Pick a variant in the bottom bar and every change becomes an override: fields you change get a marker that resets them to the base, moves (buttons or drag) become the variant's order, and delete hides. Dragging in a variant only reorders among siblings. Adding and nesting stay on the base, so variants never drift apart in structure. Hidden elements are listed in the variant menu to bring back.

## Trying it

**Try** switches clicks from selecting to running the widget's actions against `context`. The calls log (bottom left) shows each call with its arguments, and a toast names what one click asked of the app, so you can see a Save button calls `setSaved`, `sendAnalytics` and `fireToast` before it ever reaches a device.

## Export and import

**Export** has two tabs: **This widget** (its definition) and **Usage** (the code that loads it). Copy or download the JSON.

**Import** takes a pasted definition, which replaces the widget you're editing.

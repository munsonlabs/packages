The demos share one kit, `apps/demos/timeline-kit`: Bolt's story timeline, built from composables written the way Bolt writes them, with the Bolt bridge as their context. This walks through it.

```
timeline-kit/src/
  types.js        the data (Story) and the context (TimelineHost)
  sources/        one file per composable, its source beside it
  widgets/        one JSON file per example widget
  kinds.js        which stories each kind of widget is for
  themes.js       the look, light and dark
  feed.js         sample stories
  index.js        createKit
```

## 1. Name the data and the context

```js
// types.js: JSDoc typedefs, for reading
/** @typedef {{ entry: StoryEntry; saved?: boolean; progress?: number }} Story the data */
/** @typedef {BridgeService} TimelineHost the context: the bridge */
```

The context is the Bolt bridge, which the app hands to loom once:

```js
window.pugpigBridgeService = createStubNative({ stories }) // in Bolt, the native shell provides this
createApp(App).use(BoltBridgeVue) // connects, provides `globalBridge`

// App.vue
provideKit(timelineKit, useBridge()) // every widget's sources get the bridge as `ctx.context`
```

The demos use `apps/demos/bolt-bridge-stub`, which copies `@pugpigbolt/bridge`'s names and flow: a composable calls `bridge.setSaved(…)`, the native app saves and pings `pugpigUpdate('savedStories')`, the bridge reads the new state, and every widget showing that story re-renders. In a Bolt app, import the same names from `@pugpigbolt/bridge/vue` instead.

## 2. One file per composable

Each file in `sources/` holds a composable, written with no idea loom exists, and the source that plugs it in:

```js
// sources/reading.js
export function useReading(props) {
  const minutes = computed(() => props.story.entry.readtime)
  const progress = computed(() => Math.round((props.story.progress ?? 0) * 100))
  return {
    minutes,
    label: computed(() => (minutes.value ? `${minutes.value} min read` : undefined)),
    progress,
    isStarted: computed(() => progress.value > 0 && progress.value < 100),
  }
}

export const readingSource = composableSource({
  id: 'reading',
  label: 'Reading',
  fields: {
    minutes: { type: 'number' },
    label: { type: 'string', description: '"6 min read"' },
    progress: { type: 'number', description: 'Percent read' },
    isStarted: { type: 'boolean' },
  },
  use: useReading,
})
```

`composableSource` (in `sources/shared.js`) calls the composable with `{ story, index }` as live getters, so it stays reactive, and the bridge as its second argument, for composables that act. A field the composable doesn't return binds to nothing, so keep the two in step. Declare what a composable returns in `fields`, and widgets can bind to it.

The kit has fourteen: `story`, `time`, `reading`, `labels`, `topic`, `related`, `actions`, `event`, `video`, `gallery`, `podcast`, `live`, `quote` and `timeline`.

## 3. Guard what needs guarding

The bridge settles `story.locked` before widgets see a story. The kit then guards every action in one place (`paywall.js`): an action on a locked story shows the native paywall instead, whatever the widget. See [Guarding actions](/loom/core-concepts/kits-and-sources#guarding-actions).

## 4. Describe the kinds

Bolt picks a widget component by `story.entry.type`. Kinds do the same, and start new widgets from the matching example:

```js
defineKind({
  id: 'podcast',
  label: 'Podcast',
  matches: (story) => story.entry.type === 'podcast',
  sources: ['podcast', 'actions'], // what the studio suggests first
  starter: starter('podcast-row'),
})
```

One kind can cover several entry types: the video kind matches `video`, `youtube`, `vimeo`, `dailymotion`, `jwplayer`, `brightcove` and `videojs`, and its `video` source turns each platform's fields into a URL the `Video` block plays.

## 5. Make the kit

```js
export const timelineKit = createKit({
  id: 'timeline',
  themes: [timelineTheme, timelineDarkTheme],
  sources: timelineSources,
  blocks: [videoBlock, iconBlock],
  kinds: timelineKinds,
  describe: (story) => story.entry.title ?? story.entry.id,
  guard: paywallGuard,
})
```

## 6. Render a library

```js
const { widgets } = loadLibrary(timelineKit, await (await fetch('/timeline.library.json')).text())
```

```vue
<Widget v-for="(story, i) in feed" :key="story.entry.id" :kit="timelineKit" :definitions="widgets" :data="story" :index="i" :context="bridge" />
```

A story whose type no kind matches renders nothing, as it does in Bolt.

## The demos

- `apps/demos/loom-studio` edits the kit's widgets.
- `apps/demos/loom-feed` is an app that only consumes: it renders the stories the bridge brings in with a library, its own bundled one or one you import, and reports any widget it can't render. Its **Bridge** panel shows every message both ways.
- `apps/demos/loom-steps` shows how loom was built, one chapter per commit; from the timeline kit's chapter on, its examples use this kit.

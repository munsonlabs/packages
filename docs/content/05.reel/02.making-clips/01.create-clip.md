`createClip(options)` cuts `[start, end)` out of a source, crops it, draws captions, a watermark, a logo stamp and an end card into the picture, and resolves with the encoded file as a `Blob`. Video is always re-encoded (the picture changes); audio already in the target codec is copied untouched.

```ts
const clip = await createClip({
  source: video,
  start: 42,
  end: 52,
  crop: { aspect: '9:16', focus: 0.4, height: 1920 },
  captions: { cues: video.textTracks[0], style: { position: 'bottom', size: 0.05 } },
  origin: { url: location.href, title: document.title, publisher: 'Example News' },
  endCard: { logo: '/logo.svg' },
  stamp: { logo: '/logo.svg' },
  watermark: { text: 'example.com' },
  onProgress: (fraction) => bar.update(fraction),
  onWarning: (warning) => console.info(warning.message),
  signal: controller.signal,
})
```

## Options

| Option         | Type                                                     | Default               | Description                                                                                                                                                                                                                     |
| -------------- | -------------------------------------------------------- | --------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `source`       | `Blob \| string \| URL \| HTMLVideoElement`              | -                     | **Required.** A file, a URL (read with range requests, so cross-origin needs CORS) or the `<video>` being watched                                                                                                               |
| `start`        | `number`                                                 | `0`                   | Seconds on the source's timeline                                                                                                                                                                                                |
| `end`          | `number`                                                 | the source's end      | Seconds; must be after `start`                                                                                                                                                                                                  |
| `crop`         | `{ aspect?, focus?, height? }`                           | centred 9:16          | [See crop](/reel/making-clips/crop)                                                                                                                                                                                             |
| `captions`     | `{ cues?, tracks?, track?, style? }`                     | -                     | Cues, a `TextTrack`, WebVTT text or a WebVTT file's URL; or `tracks` to choose from and a `track` id from `listCaptionTracks`; `style` overrides the caption look (`CaptionStyle`); [see captions](/reel/making-clips/captions) |
| `track`        | `'auto' \| 'smallest' \| 'largest'`                      | `'auto'`              | Which video track to read when there are several, such as HLS variants; [see below](#hls-and-several-video-tracks)                                                                                                              |
| `origin`       | `{ url, title?, publisher? }`                            | -                     | Where the clip came from; drives metadata, the deep link and the end card. [See origin](/reel/making-clips/origin-and-links)                                                                                                    |
| `metadata`     | `boolean`                                                | `true` with an origin | Write the origin into the file's tags                                                                                                                                                                                           |
| `endCard`      | `EndCardOptions \| boolean`                              | -                     | Frames after the clip with the logo, headline and the article's address; [see end card](/reel/making-clips/end-card)                                                                                                            |
| `stamp`        | `{ logo, position?, size?, margin?, opacity? }`          | -                     | A logo in a corner of every clip frame, clear of the apps' buttons; [see the stamp](/reel/making-clips/end-card#a-logo-stamp-over-the-clip)                                                                                     |
| `watermark`    | `{ text, position?, background?, color?, size?, font? }` | -                     | A thin strip of text over every clip frame, along the `'top'` (default) or `'bottom'` edge                                                                                                                                      |
| `audio`        | `boolean`                                                | `true`                | `false` drops the audio; [see output](#output) for when a clip is silent anyway                                                                                                                                                 |
| `onProgress`   | `(fraction: number) => void`                             | -                     | Called with 0 to 1, rising, ending at exactly 1                                                                                                                                                                                 |
| `onWarning`    | `(warning: ClipWarning) => void`                         | `console.warn`        | Something left out of a clip that was still made: `{ reason: 'logo-unavailable' \| 'captions-unavailable' \| 'audio-unavailable', target: 'endCard' \| 'stamp' \| 'captions' \| 'audio', message }`                             |
| `stallTimeout` | `number`                                                 | `15`                  | Seconds an H.264 encoder may hold frames without output before the attempt is abandoned (`Infinity` waits for ever); [see output](#output)                                                                                      |
| `signal`       | `AbortSignal`                                            | -                     | Aborts; the promise rejects with `signal.reason`                                                                                                                                                                                |
| `cache`        | `PlaylistCache`                                          | -                     | HLS playlists already read by `canClip`, `createStoryboard` or `listCaptionTracks` with the same cache are not fetched again; [see below](#reading-playlists-once)                                                              |

## Output

- **Format**: always an MP4 (`video/mp4`) with H.264 video and AAC audio, the format every platform takes. A browser with no H.264 encoder at the clip's size cannot clip (`no-video-encoder`).
- **Audio**: AAC is copied packet for packet, so an AAC source needs no audio encoder. Other audio (Opus in a WebM, say) is encoded as AAC. Where the browser has no AAC encoder (Firefox), such a source gives a **silent** clip, and `onWarning` gets `{ reason: 'audio-unavailable', target: 'audio', message }`. `canClip(source).plan.audio` tells you in advance: `'copy'`, `'encode'`, `'none'` (no audio, or `audio: false`) or `'unavailable'`.
- **Size**: at least 1080x1920 for 9:16 (the largest frame of the aspect that fits 1080x1920, or 1920x1080 for a landscape aspect), or the crop window's own size when that is bigger; a 720p or 1080p source gives 1080x1920 at 9:16. Smaller sources are scaled up so the captions, end card and stamp are drawn sharp at the size a phone shows them; `crop.height` overrides it ([see crop](/reel/making-clips/crop#output-size)). Dimensions are always even.
- **A stalled encoder**: an H.264 encoder that holds frames without output for `stallTimeout` seconds (default 15) is abandoned and the clip tried once with a software encoder; failing that, `createClip` rejects with a `ClipError` `'encoder-stalled'` ([see browser support](/reel/reference/browser-support#a-stalled-encoder)).
- **Duration**: `end - start`, plus the end card's `duration` when there is one. The end card is silent.
- **Metadata**: none from the source, ever (it can carry a location, a device, a different title). With an `origin`, the clip says where it came from.

## HLS and several video tracks

An HLS master playlist offers the same video at several sizes (variants). `canClip` describes the largest one this browser can decode (`info.width`, `info.height`) and lists them all in `info.videoTracks` (`{ index, width, height, bitrate, codec }`, from each variant's `RESOLUTION`, `BANDWIDTH` and `CODECS`), reading nothing but playlists.

The crop is planned on the largest track. `createClip` then reads the **smallest variant that still covers the output** after the crop: a 180-pixel-high clip of a 1080p stream reads the 180p variant, a 1080x1920 clip (the default) the largest one, and only that variant's segments are downloaded. The audio is the one presented with that variant (its own muxed audio, or its `AUDIO` group's default), never another variant's.

| `track`      | Reads                                                                     |
| ------------ | ------------------------------------------------------------------------- |
| `'auto'`     | The smallest track that covers the output, else the largest (the default) |
| `'smallest'` | The smallest track, whatever the output size                              |
| `'largest'`  | The largest track                                                         |

Tracks this browser cannot decode (an HEVC variant in Firefox, say) are skipped whatever the choice.

### Reading playlists once

`canClip`, `createStoryboard`, `createClip`, `listCaptionTracks` and `loadCaptionTrack` each read the master playlist (and the media playlists they need) on their own. When one flow calls several of them, share a `PlaylistCache`:

```ts
import { canClip, createClip, createPlaylistCache, createStoryboard } from '@munsonlabs/reel'

const cache = createPlaylistCache()
const check = await canClip(hls, { cache })
const board = await createStoryboard({ source: hls, cache })
const clip = await createClip({ source: hls, start, end, cache })
cache.clear() // done: forget the playlists, abort any read still in flight
```

The cache fetches each `.m3u8` once, whole, and answers every later request for it, Mediabunny's range requests included, from memory; segments are never cached. A master playlist is kept until `clear()`; a media playlist only if it is complete (`#EXT-X-ENDLIST`), so a live playlist is read afresh every time. A response that fails or was redirected is not kept. Keep a cache for one flow (the picker makes one per opening), not for the page's lifetime. Each caller's `signal` aborts only its own wait.

## Cancelling

```ts
const controller = new AbortController()
const pending = createClip({ source, start, end, signal: controller.signal })
cancelButton.onclick = () => controller.abort()

try {
  await pending
} catch (error) {
  if (controller.signal.aborted) {
    // error is controller.signal.reason; nothing is left running or open
  }
}
```

## Errors

A logo that cannot be loaded (or that is cross-origin without CORS headers) is not an error: the clip is made without it and `onWarning` is told.

`createClip` rejects with a `ClipError` whose `reason` is one of the [blocker codes](/reel/reference/blockers) when the source cannot be clipped, with a `RangeError` for an empty or inverted range, and with the signal's reason when aborted. Check with `canClip` first to show the reason before anyone presses export.

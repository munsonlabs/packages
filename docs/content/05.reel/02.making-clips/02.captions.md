Short-form video is mostly watched muted, so captions belong in the picture. `captions.cues` takes whatever you have:

| `cues`         | Notes                                                                                                                                                   |
| -------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `TextTrack`    | The track the viewer is watching, e.g. `video.textTracks[0]`. Its `mode` must not be `'disabled'` (cues load only when it is `'hidden'` or `'showing'`) |
| `string`       | The text of a WebVTT file, or the URL of one, absolute or relative to the page ([text or URL?](#text-or-url))                                           |
| `URL`          | The URL of a WebVTT file                                                                                                                                |
| `CaptionCue[]` | `{ start, end, text }` in seconds on the **source's** timeline                                                                                          |

Cue times stay on the source's timeline, the same times the `<track>` uses: reel shifts them for you. VTT markup (`<v Speaker>`, `<i>`, karaoke timestamps) is stripped and entities decoded.

Captions are WebVTT only. Convert SRT to WebVTT first.

```ts
await createClip({
  source: video,
  start: 42,
  end: 52,
  captions: {
    cues: video.textTracks[0], // or '/captions/interview.vtt', or the file's text
    style: { size: 0.05 }, // optional overrides on the caption look; see Style below
  },
})
```

## Caption files by URL

A URL is fetched with the clip's `signal`, so aborting the clip aborts the download. The file must be WebVTT, starting with its `WEBVTT` header, whatever its name or content type.

A file on another origin needs `Access-Control-Allow-Origin`, like any `fetch`.

**Captions that will not load never fail a clip.** A file that cannot be fetched (an HTTP error, or CORS), a file that is not WebVTT (an HTML error page served with a 200, say, or an SRT file), or an HLS subtitles rendition whose playlist or segments fail: `createClip` makes the clip without captions and calls [`onWarning`](/reel/making-clips/create-clip) (by default `console.warn`), as it does for a logo:

```ts
await createClip({
  source,
  captions: { cues: '/captions/interview.vtt' },
  onWarning: ({ reason, target, message }) => console.info(reason, target, message),
  // 'captions-unavailable' 'captions' 'reel: the captions are left out. The captions at https://… could not be loaded: the server answered 404 Not Found.'
})
```

`canClip` never reports it: the source itself is fine. An unknown `track` id is a mistake in the call, not a load failure, and still rejects (`RangeError`). In the [picker](/reel/picker/picker#captions) the same failure is a note and a non-fatal `reel-error`, and the clip is made without them.

`loadCaptions(input, { signal })` turns any of these inputs into cues without making a clip; `toCues(input)` does the same for inputs that need no fetching. Called directly, `loadCaptions` and `loadCaptionTrack` do reject when the file cannot be fetched or read, with an `Error` whose message says which.

### Text or URL?

A string is **caption text** when, after an optional byte-order mark and leading whitespace, it starts with `WEBVTT`, which every WebVTT file does. **Anything else is a URL**, resolved against `document.baseURI`: `captions.vtt`, `/media/clock.fr.vtt`, `https://cdn.example.com/a.vtt`, a `blob:` or `data:` URL. `isVttFile(value)` applies the rule; an empty string is text with no cues.

## Several caption tracks

To offer more than one file (languages, say), pass `tracks`: a list in the shape of [video-player's `tracks` prop](/video-player/features/captions), `{ src, kind?, srclang?, label?, default? }`, where each `src` may be a WebVTT file's URL or WebVTT text. Choose one with `track: 'passed:<n>'`, `n` being its position in the list:

```ts
const tracks = [
  { src: '/captions/interview.en.vtt', srclang: 'en', label: 'English' },
  { src: '/captions/interview.fr.vtt', srclang: 'fr', label: 'Français' },
]
await createClip({ source, start: 42, end: 52, captions: { tracks, track: 'passed:1' } })
await createClip({ source, start: 42, end: 52, captions: { tracks } }) // the default track
```

**Without `track`, the default is burned in**: the track marked `default`, else the first whose `srclang` matches `navigator.language` (exactly, then by its primary subtag, so `fr` matches `fr-CA`), else the first. Passed tracks take precedence over the source's own: `track: 'hls:0'` still picks a rendition, but only by asking for it. `cues`, when given, wins over both.

`listCaptionTracks(source, { tracks })` lists the passed tracks first, as `{ id: 'passed:<n>', kind: 'passed', language: srclang, label, default }` (`default` on the one the rule picks), then the source's own; nothing is fetched for passed tracks until one is loaded. `loadCaptionTrack(source, 'passed:1', { tracks })` loads one. The ids map like this:

| id         | Track                                                         |
| ---------- | ------------------------------------------------------------- |
| `passed:n` | `tracks[n]`, the tracks passed in                             |
| `hls:n`    | the master playlist's n-th `EXT-X-MEDIA:TYPE=SUBTITLES` entry |
| `text:n`   | a `<video>` source's `textTracks[n]`                          |

## The source's own caption tracks

`listCaptionTracks(source)` lists what a source carries itself, and `captions: { track: id }` burns one in:

- **HLS subtitle renditions**: the `EXT-X-MEDIA:TYPE=SUBTITLES` entries of a master playlist (any URL ending `.m3u8`, or a `<video>` playing one natively), read from the master alone.
- **A `<video>`'s text tracks** of kind `captions` or `subtitles`.

```ts
import { createClip, listCaptionTracks } from '@munsonlabs/reel'

const tracks = await listCaptionTracks('https://cdn.example.com/show/master.m3u8')
// [{ id: 'hls:0', kind: 'hls', language: 'en', label: 'English', default: true }, …]
await createClip({ source: 'https://cdn.example.com/show/master.m3u8', start: 42, end: 52, captions: { track: 'hls:0' } })
```

`cues`, when given, wins over `track`. `loadCaptionTrack(source, id, { start, end })` returns a track's cues without making a clip. A [`cache`](/reel/making-clips/create-clip#hls-and-several-video-tracks) passed to both, and to `canClip` and `createClip`, means the master playlist is fetched once for all of them.

**Only what the clip needs is fetched.** For an HLS rendition, reel reads its media playlist and fetches just the WebVTT segments whose time overlaps `[start, end)`. Each segment's `X-TIMESTAMP-MAP=MPEGTS:…,LOCAL:…` header is honoured: cue time `LOCAL` is media time `MPEGTS / 90000`, and the clip timeline's 0 is the media's first timestamp (read once from the first segment of the lowest variant), so a stream whose video starts at PTS 10s, as Apple's and Mux's segmenters write it, still lines up. A segment without the header is taken at face value. Cues repeated across a segment boundary are kept once.

**Text tracks load on demand.** A `disabled` track has no cues, so reel sets it to `hidden` (which loads its `<track>` file without showing anything), reads the cues, and sets it back to `disabled`. A `showing` or `hidden` track is left alone.

The picker burns in whichever of these its preview player is showing; see [its captions](/reel/picker/picker#captions).

## Style

Captions have one look: **white bold text on a translucent dark box, near the bottom**, one box per line. Every size is a fraction of the frame (the font and vertical distances of the height, widths of the width), so a caption looks the same at 404x720 and 1080x1920. Long cues wrap onto more lines, keeping the cue's own line breaks; a word wider than a line is left whole.

`style` takes overrides, each optional:

```ts
captions: { cues } // the look as it is
captions: { cues, style: { size: 0.05, color: '#ffd400' } } // bigger, yellow text
captions: { cues, style: { background: null } } // no box
captions: { cues, style: { margin: 0.28 } } // higher up
```

| Style        | Default              | Description                                                       |
| ------------ | -------------------- | ----------------------------------------------------------------- |
| `fontFamily` | system sans-serif    | CSS font family                                                   |
| `fontWeight` | `700`                |                                                                   |
| `size`       | `0.045`              | Font size as a fraction of the height                             |
| `color`      | `#ffffff`            |                                                                   |
| `background` | `rgba(0, 0, 0, 0.6)` | A box behind each line; `null` for none                           |
| `position`   | `'bottom'`           | `'top'`, `'middle'` or `'bottom'`                                 |
| `margin`     | `0.14`               | Distance from that edge to the block, as a fraction of the height |
| `maxWidth`   | `0.86`               | Widest line before wrapping, as a fraction of the width           |

Captions sit near the bottom, where they read well on a desktop or a TV; a host posting clips to TikTok or Reels, whose own text covers roughly the bottom quarter of a vertical video, can raise them with `position` and `margin` (`margin: 0.28`, say).

Each cue's lines are wrapped once, not once per frame. The [picker](/reel/picker/picker#captions) previews captions with the very same painter, laid out at the export's size and scaled to the preview, so its lines break exactly where the clip's do.

::note
Captions are drawn on the cropped, upright frame, so they stay horizontal and inside the 9:16 window even for a [rotated phone video](/reel/making-clips/crop#rotated-video).
::

`crop` picks the largest window of the requested aspect that fits inside the frame, centred on `focus`.

```ts
crop: { aspect: '9:16', focus: 0.3, height: 1920 }
```

| Option   | Type                                                      | Default   | Description                                                                                                                     |
| -------- | --------------------------------------------------------- | --------- | ------------------------------------------------------------------------------------------------------------------------------- |
| `aspect` | `'9:16' \| '4:5' \| '1:1' \| '16:9' \| 'source' \| 'w:h'` | `'9:16'`  | `'source'` keeps the whole frame                                                                                                |
| `focus`  | `number \| { x?, y? }`                                    | centre    | Where the window's centre sits, 0 (left/top) to 1 (right/bottom), clamped so the window never leaves the frame. A number is `x` |
| `height` | `number`                                                  | see below | Output height; the width follows the aspect. Overrides the default in either direction                                          |

`planCrop(width, height, crop)` returns the same window and output size `createClip` will use, so a preview can show exactly what will be cut. The [picker](/reel/picker/picker) uses it to turn the focus into a CSS `object-position`.

## Output size

By default a clip is the **largest frame of its aspect that fits 1080x1920** (1920x1080 for a landscape aspect), or the crop window's own size when that is bigger. Small sources are scaled up; a window already bigger is never scaled down.

| Source | Aspect     | Window    | Output    |
| ------ | ---------- | --------- | --------- |
| 720p   | `9:16`     | 405x720   | 1080x1920 |
| 1080p  | `9:16`     | 608x1080  | 1080x1920 |
| 4K     | `9:16`     | 1215x2160 | 1214x2160 |
| 720p   | `1:1`      | 720x720   | 1080x1080 |
| 720p   | `4:5`      | 576x720   | 1080x1350 |
| 540p   | `'source'` | 960x540   | 1920x1080 |

Why scale up: a clip is watched full screen on a phone, about 1080 pixels wide. Everything reel paints on it (captions, the end card, the stamp, the watermark) is drawn at the output's size, so at a 720p source's own 404x720 that text would be magnified about 2.7 times by the phone and look soft. At 1080x1920 it is drawn at the size it is seen; in the tests its edges are about twice as sharp. The video itself is scaled with the canvas's high-quality smoothing, and gets no sharper than its source. The cost is time and bytes: about twice the export time and three to five times the file size of the window's own size ([numbers](/reel/reference/browser-support#speed)).

Set `height` to override: `planCrop(w, h, crop).height` (the window's own height) for the smallest, fastest file, or a larger number for more.

## Why reel draws the crop itself

WebKit's `drawImage(VideoFrame, sx, sy, sw, sh, dx, dy, dw, dh)` ignores the source rectangle and draws the whole frame. A crop done that way (including Mediabunny's own `crop` option) comes out uncropped and squashed in Safari. Reel draws the whole frame scaled and shifted so the canvas edges do the cutting, which every engine gets right, scaling up or down. A test pins the WebKit behaviour, so the workaround can be dropped when WebKit fixes it.

## Rotated video

Phones store upright video as landscape frames plus a rotation in the track header. Reel works in **display** orientation throughout: `canClip` reports the size as you see it (480x640, not 640x480), the crop and focus apply to that picture, captions are drawn upright on it, and the clip carries the turn in its pixels with no rotation metadata, so every player shows it the same way. This is tested with 90 and 270 degree fixtures in Chromium, WebKit and Firefox.

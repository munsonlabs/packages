`endCard` adds a few seconds after the clip, faded in over its last frame: your logo, the publisher, the headline and, as the call to action, **the article's address in large type**, such as `acme.news/2026/10/tides-rising`. Everything defaults from `origin`, so `endCard: true` is usually enough.

```ts
await createClip({
  source,
  start: 42,
  end: 52,
  origin: { url: 'https://www.acme.news/2026/10/tides-rising', title: 'Tides are rising faster than expected', publisher: 'Acme News' },
  endCard: { logo: 'https://cdn.acme.news/logo.svg' },
  stamp: { logo: 'https://cdn.acme.news/logo.svg' }, // the same logo in the corner of every clip frame
})
```

## Options

| Option       | Type                                  | Default                         | Description                                                                       |
| ------------ | ------------------------------------- | ------------------------------- | --------------------------------------------------------------------------------- |
| `duration`   | `number`                              | `2.5`                           | Seconds the card stays up; the clip gets that much longer                         |
| `title`      | `string`                              | `origin.title`                  | The headline                                                                      |
| `publisher`  | `string`                              | `origin.publisher`              | Drawn in the accent colour, above the headline                                    |
| `displayUrl` | `string`                              | `origin.url`, made readable     | The address shown on the card. [See the address](#the-address)                    |
| `cta`        | `string`                              | `'Watch the full video at'`     | The line above the address; `''` hides it                                         |
| `logo`       | image, `Blob` or URL                  | -                               | Loaded once before the clip starts. [See logos](#logos-from-a-url)                |
| `theme`      | `{ background, color, accent, font }` | deep green, white, gold, system | Colours and font; the address sits on an `accent` pill in the `background` colour |
| `draw`       | `(ctx, info) => void`                 | -                               | Replaces the renderer                                                             |

The card is silent: the audio track ends with the clip.

## The address

Most clips are watched on a phone, in TikTok, Reels, Shorts or a WhatsApp chat, so the card's job is to give the viewer something they can read and type, or search for. By default that is the article itself, `origin.url`, without the `#ml-t=` range, made readable: no `https://`, no `www.`, no query string, no hash and no trailing slash, with the path percent-decoded. An internationalised domain comes out in its `xn--` form, so set `displayUrl` for one.

```
https://www.acme.news/2026/10/tides-rising?utm_source=x#ml-t=4,9  →  acme.news/2026/10/tides-rising
```

It is drawn as large as the card's width allows. When an address is too long even at the smallest size, it is shortened in the middle: whole path segments go first, so the domain and the final segment, usually the slug that says what the story is, stay whole (`acme.news/2026/…/tides-rising`). Only a slug that is too long by itself is cut mid-word.

Set `displayUrl` to show something else, such as a shorter vanity address (`acme.news/tides`). It is shown as given when it fits.

`readableUrl(url, maxWidth?, measure?)` is exported, for showing the same address elsewhere. Without `measure`, `maxWidth` counts characters; on a canvas, pass the context's measurer:

```ts
import { readableUrl } from '@munsonlabs/reel'

readableUrl('https://www.acme.news/2026/10/tides-rising?utm=x#ml-t=4,9') // 'acme.news/2026/10/tides-rising'
readableUrl('https://www.acme.news/2026/10/03/climate/tides-rising', 26) // 'acme.news/…/tides-rising'
ctx.font = '700 48px system-ui'
readableUrl(url, 600, (text) => ctx.measureText(text).width)
```

## No QR code

A QR code only helps someone with a second device. A phone viewer cannot scan a code on their own screen, and on a phone, where most clips are watched, it would take up to 40% of the card for nothing. So the card has none and leads with the readable address instead. A custom `draw` that wants one for a TV or a big screen gets the deep link as `info.url` and can draw it with any QR library.

## Logos from a URL

`endCard.logo` and `stamp.logo` take an image, a `Blob` or a URL. A URL is loaded through an `<img>` with `crossOrigin = 'anonymous'`, so it can be on a CDN:

- **Same-origin** URLs always work.
- **Cross-origin** URLs need CORS headers (`Access-Control-Allow-Origin`). Without them, a logo would taint the clip's canvas and every `VideoFrame` made from it would throw, so reel finds out first: it loads the image, test-draws it to a 1x1 canvas and reads it back.
- **SVG** works from a URL, a data URL, a `Blob` or an `<img>`. It is rasterised sharply; one with only a `viewBox` and no `width`/`height` is drawn at a fallback size and trimmed to what is actually drawn.

A logo that cannot be used never fails the export. The clip is made without it and a warning goes to `onWarning` (or `console.warn` without one); in [the picker](/reel/picker/picker) it is a non-fatal `reel-error`:

```ts
await createClip({
  // …
  endCard: { logo: 'https://other.example/logo.png' },
  onWarning: (warning) => console.info(warning.reason, warning.target, warning.message),
  // 'logo-unavailable' 'endCard' 'reel: the end card logo is left out. https://other.example/logo.png could not be used: …'
})
```

## A logo stamp over the clip

`stamp` draws a logo in a corner of every frame of the clip (not the end card, which has its own logo), so a clip carries your brand however it is cut and reshared:

```ts
stamp: { logo: '/logo.svg', position: 'top-right', size: 0.18, opacity: 0.9 }
```

| Option     | Type                                                           | Default       | Description                                                                                  |
| ---------- | -------------------------------------------------------------- | ------------- | -------------------------------------------------------------------------------------------- |
| `logo`     | image, `Blob` or URL                                           | -             | **Required.** Loaded and checked like the card's logo                                        |
| `position` | `'top-left' \| 'top-right' \| 'bottom-left' \| 'bottom-right'` | `'top-right'` |                                                                                              |
| `size`     | `number`                                                       | `0.18`        | The logo's width as a fraction of the frame width; a tall logo is limited to the same height |
| `margin`   | `number \| { x?, y? }`                                         | per corner    | Distance from the edges, as fractions of the width (`x`) and height (`y`)                    |
| `opacity`  | `number`                                                       | `0.9`         |                                                                                              |

### Safe areas

Short-form apps draw their own interface over a vertical video: a status bar and feed tabs along the top, the account name, caption and sound along the bottom, and the like, comment and share buttons in a rail down the right. The default margins keep the stamp out from under all of it:

| `position`     | Default `margin`       | Clears                                                   |
| -------------- | ---------------------- | -------------------------------------------------------- |
| `top-left`     | `{ x: 0.05, y: 0.11 }` | the status bar and the feed tabs                         |
| `top-right`    | `{ x: 0.05, y: 0.11 }` | the status bar and the search button                     |
| `bottom-left`  | `{ x: 0.05, y: 0.24 }` | the account name, caption and sound line                 |
| `bottom-right` | `{ x: 0.2, y: 0.24 }`  | the caption area and the action rail down the right side |

`top-right` is the default because it is clear on every app and stays away from bottom captions. A bottom stamp can meet burned-in captions, which sit 14% from the bottom by default. `planStamp(width, height, logo, options)` returns the box a stamp will be drawn in, for previews.

## Your own card

`draw(ctx, info)` is called for every frame of the card on the clip's own canvas, which already holds the clip's last frame. `info` has everything resolved:

| `info`                                    | Description                                                              |
| ----------------------------------------- | ------------------------------------------------------------------------ |
| `width`, `height`                         | The output size                                                          |
| `time`, `duration`, `progress`            | Seconds into the card, its length and `time / duration`                  |
| `title`, `publisher`, `displayUrl`, `cta` | The resolved text; `displayUrl` is readable but not yet shortened to fit |
| `url`                                     | The `#ml-t=` deep link back to the moment, or `null` without an origin   |
| `logo`                                    | An `ImageBitmap`, or `null` (none given, or it could not be loaded)      |
| `theme`                                   | The resolved theme                                                       |
| `lastFrame`                               | The clip's last frame as an `OffscreenCanvas`                            |

```ts
import { drawEndCard } from '@munsonlabs/reel'

endCard: {
  draw(ctx, info) {
    drawEndCard(ctx, info) // the default, then add to it
    ctx.fillStyle = info.theme.accent
    ctx.fillRect(0, info.height - 12, info.width * info.progress, 12) // a progress bar
  },
}
```

## Watermark

For a lighter touch, `watermark` runs one line of text along the top (or bottom) of every clip frame, not the card:

```ts
watermark: { text: 'example.com · Example News', position: 'top' }
```

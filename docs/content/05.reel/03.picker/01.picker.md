The picker is the whole "clip this" flow, inline on the page's own [`@munsonlabs/video-player`](/video-player/getting-started/introduction). The player is the preview: opening the picker pauses it on the moment, loops the range you pick through its [`setClipRange()`](/video-player/features/clip-range) and draws a 9:16 window over its picture, which you drag to reframe. Under the player sits a panel with a filmstrip to set the range, end-card and logo toggles, export with progress and cancel, then the clip with **Share** (the file plus the deep link), **Download** and **Copy caption with link**.

::reel-example
::

The picker is Vue components, `ReelPicker` from `@munsonlabs/reel/vue`, and `<ml-reel-picker>` from `@munsonlabs/reel/element` is the same component as a custom element. Both need **`vue` and `@munsonlabs/video-player`**, peer dependencies shared with the page's own player (see [installation](/reel/getting-started/installation)). Reel's core and Mediabunny load the first time a picker opens.

::tabs
:::tabs-item{label="Vue" icon="i-vscode-icons:file-type-vue"}

```vue
<script setup lang="ts">
import { ref } from 'vue'
import { VideoPlayer, type PlayerHandle } from '@munsonlabs/video-player'
import { ReelPicker } from '@munsonlabs/reel/vue'
import '@munsonlabs/video-player/style'
import '@munsonlabs/reel/style'

const src = '/video/interview.mp4'
const player = ref<PlayerHandle>()
const open = ref(false)
</script>

<template>
  <VideoPlayer ref="player" :src="src" deep-link="interview" />
  <button @click="open = true">Clip this</button>
  <ReelPicker
    v-model:open="open"
    :player="player"
    :source="src"
    :origin="{ url: 'https://example.com/interview', title: 'The interview', player: 'interview' }"
    @export="({ blob, link }) => console.log(blob, link)"
  />
</template>
```

:::
:::tabs-item{label="Web component" icon="i-vscode-icons:file-type-html"}

```html
<ml-video-player id="interview" src="/video/interview.mp4" deep-link="interview"></ml-video-player>
<ml-reel-picker id="picker" for="interview" src="/video/interview.mp4"></ml-reel-picker>
<button id="clip">Clip this</button>

<script type="module">
  import '@munsonlabs/video-player/element'
  import '@munsonlabs/reel/element'

  const picker = document.getElementById('picker')
  picker.origin = { url: location.href, title: document.title, publisher: 'Example News', player: 'interview' }
  document.getElementById('clip').addEventListener('click', () => picker.show())
  picker.addEventListener('reel-export', (event) => console.log(event.detail.link))
</script>
```

`for` is the id of an `<ml-video-player>`; for a handle you already hold, set the `player` property instead. `origin` is an object, so it goes through a property; `src` (a URL) and `open` also work as attributes. The element renders without a shadow root, like video-player's elements, and puts reel's stylesheet on the page once. It does not load the player's: the page already has the player. Vue and `@munsonlabs/video-player` are imported from the page (with a bundler, or an import map).
:::
::

A picker placed inside a `<VideoPlayer>`'s default slot needs neither `player` nor `for`: it finds the enclosing player. See [the recipe](/reel/picker/video-player).

## Properties

| Property             | Type                                                  | Description                                                                                                                                                   |
| -------------------- | ----------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `player`, `for`      | `PlayerHandle \| null`, `string`                      | The player to clip: its handle (the `VideoPlayer` template ref), or the id of an `<ml-video-player>` (attribute `for`). Neither inside a `VideoPlayer`'s slot |
| `source`, `src`      | `Blob \| string \| URL \| HTMLVideoElement`, `string` | What to read. Defaults to the player's own file, unless it plays a `blob:` (MediaSource, as an HLS stream through hls.js does): then pass the stream's URL    |
| `origin`             | `{ url, title?, publisher?, player? }`                | For the end card, metadata and the shared link; `player` is the id in the player's `deep-link`                                                                |
| `endCard`            | `EndCardOptions \| boolean`                           | The card used when its toggle is on; `false` starts with the toggle off                                                                                       |
| `watermark`          | `WatermarkOptions`                                    | Drawn over every clip                                                                                                                                         |
| `open`               | `boolean`                                             | The element's `open` attribute, or `v-model:open` on `ReelPicker`                                                                                             |
| `state`              | read-only                                             | `'closed' \| 'loading' \| 'editing' \| 'blocked' \| 'exporting' \| 'done'`, mirrored on `data-state`                                                          |
| `range`, `cropFocus` | read-only                                             | The selection in seconds, and the crop focus (0 to 1 per axis)                                                                                                |
| `captionPosition`    | read-only                                             | `'top' \| 'middle' \| 'bottom'`: where the captions sit in the window and the clip                                                                            |

Methods: `show()`, `close()`, `export()`, `cancel()`, `share()` (resolves `'shared'`, `'downloaded'` or `'dismissed'`), `download()` and `copyCaption()` (resolves `'copied'` or `'selected'`). After an export, `shareCaption` holds the caption text. On `ReelPicker` they are on its template ref (typed as `PickerApi`).

The viewer's position and the captions are not properties: both come from the player. Only where the captions sit is the picker's.

## Events

| Event                         | `detail`                     | When                                                                      |
| ----------------------------- | ---------------------------- | ------------------------------------------------------------------------- |
| `reel-open`, `reel-close`     | -                            |                                                                           |
| `reel-range`                  | `{ start, end }`             | A handle or the selection moved                                           |
| `reel-export`                 | `{ blob, start, end, link }` | A clip is ready                                                           |
| `reel-cancel`                 | -                            | An export was cancelled                                                   |
| `reel-share`, `reel-download` | the export detail            |                                                                           |
| `reel-copy`                   | `{ text, result }`           | The caption was copied (`'copied'`) or selected in a field (`'selected'`) |
| `reel-error`                  | `{ reason, message, fatal }` | See below                                                                 |

`reel-error` is fatal (`fatal: true`, nothing was made) for a [blocker](/reel/reference/blockers), `'no-player'`, `'no-source'`, `'export-failed'` or `'encoder-stalled'`. A stalled export (the video encoder stopped responding, see [browser support](/reel/reference/browser-support#a-stalled-encoder)) never leaves the panel in "exporting": it goes back to editing, says "The export stalled. Try again." (`labels.exportStalled`) and the export button reads "Try again" (`labels.retry`) until the next export. It is not fatal (`fatal: false`) when something optional is missing and the picker carries on, with a quiet note in the panel:

| `reason`                 | What happened                                                                                                          |
| ------------------------ | ---------------------------------------------------------------------------------------------------------------------- |
| `logo-unavailable`       | The logo could not be loaded (or is cross-origin without CORS); the clip was made without it                           |
| `thumbnails-unavailable` | The filmstrip's thumbnails could not be made; the range works over plain placeholders                                  |
| `captions-unavailable`   | The chosen captions would not load (an HTTP error, CORS, not a caption file); the preview and the clip go without them |
| `audio-unavailable`      | The source's audio is not AAC and this browser cannot encode AAC (Firefox); the clip is silent                         |

The Vue component emits the same as `export`, `cancel`, `share`, `download`, `copy`, `error`, `range`, `open`, `close` and `update:open`, each with the `detail` as its argument.

Nothing is thrown. A missing source, a YouTube URL, a video behind DRM: the panel says why in its status line and fires `reel-error`, with the export button disabled. A picker with no player (`'no-player'`) or a player on a MediaSource with no `source` given (`'no-source'`) is blocked the same way.

## The player is the preview

Opening the picker (`show()`, or `open` set) pauses the page's player, takes its position as the moment, and opens a range around it, ten seconds by default. The picker then seeks the player to the start of the range and plays it, looping: it calls `setClipRange(range, { end: 'loop' })` whenever the range changes, and the player jumps back within about a frame of the end. Closing it calls `setClipRange(null)` and leaves the player paused where it is. Sound, captions and quality are the player's: the panel controls the first two through the player's handle, and quality stays the player's own.

**The crop window** is drawn over the player's picture, inside the player's shell: a 9:16 box the clip keeps, with everything outside it dimmed (`--reel-scrim`). Drag it to reframe, or focus it and use the arrow keys. The stamp preview and the captions are drawn inside it, as the clip will have them.

**The panel** is wherever you put `<ReelPicker>`, usually right under the player. It holds the title and a close button, the filmstrip with its handles and playhead, the player's own controls (play and pause, the time within the clip, mute, captions), the end-card and logo toggles, the caption position, **Export** with progress and **Cancel**, the status line and any notes. When the clip is made, the finished clip, with **Share**, **Download**, **Copy caption with link** and **Edit again**, replaces them.

**The player's controls** in the panel are [`@munsonlabs/video-player`'s headless controls](/video-player/api/controls) on the page's player. While the editor is open the player's own HUD is hidden (the picker calls [`setControls(false)`](/video-player/api/methods) on the handle, and `setControls(null)` on close), so nothing sits under the crop window and the panel is the one place to play, pause, mute and choose captions. The time reads from the start of the clip, like `0:01 / 0:10`. While the window is over the picture, the browser's own rendering of the player's captions is hidden (reel puts the class `reel-previewing` on the player's shell and hides its `::cue`), so the only captions on show are reel's, painted inside the window. The caption track stays on: the player still reports it and reel still reads its cues.

The filmstrip's playhead moves with the picture: while the player plays, the picker reads the time from its `<video>` (the handle's `mediaElement`) on every presented frame, with `requestVideoFrameCallback` (or `requestAnimationFrame`), rather than following `timeupdate`, which comes about four times a second. That loop runs only while the editor shows and the player plays in a visible tab, and stops on pause, export and close. During an export the player rests, and picks up again afterwards if it was playing.

**Clicking and dragging on the filmstrip:**

| Where                           | Click                                   | Drag                                                    |
| ------------------------------- | --------------------------------------- | ------------------------------------------------------- |
| Inside the selection            | Seeks the player there; the range stays | Past 4px, slides the whole range (keeping its length)   |
| The playhead                    | Seeks there                             | Scrubs the player, held inside the selection            |
| A handle                        | Grabs it                                | Moves that end of the range; the player shows its frame |
| The filmstrip outside the range | Nothing                                 | Nothing                                                 |

A press on the selection that moves less than 4px before it is released counts as a click, so a slightly shaky click still seeks rather than nudging the range. The playhead hides while a handle or the selection is dragged.

## What it clips

The picker reads `source` (or `src`), else the player's own file. A player playing an MP4 or WebM through a plain `<video src>` needs nothing more. A player on an HLS stream through hls.js plays a `blob:` MediaSource, which cannot be read back, so give the stream's playlist URL as `source`; without it the picker is blocked with `'no-source'`. Without a player at all (no `player`, no `for`, and no enclosing `VideoPlayer`) it is blocked with `'no-player'`.

Given the playlist URL, the filmstrip is built from the stream's lowest variant and the export reads the smallest variant that covers the clip.

## The filmstrip

The strip has its final size and ten placeholder slots the moment the editor opens, and each thumbnail is painted as soon as it is decoded. Thumbnails are keyframes (the nearest at or before each slot's time) from the smallest video track that fills a slot, so an HLS stream's filmstrip comes from its lowest variant and decodes one frame per keyframe. Closing the picker stops it at once, cancelling downloads in flight. If thumbnails cannot be made, the slots stay plain, the panel notes "Thumbnails unavailable", and the range works as before.

## Captions

**What the viewer has on is what the clip gets.** The captions are the player's own tracks, and whichever the viewer has showing when they press Export is burned in. Captions off in the player means a clip without captions. The picker takes no captions of its own: the captions button in the panel cycles the player's tracks (what is on show is burned in, **Off** means none), and the tracks come from the player: give it the tracks (its [`tracks` prop](/video-player/features/captions), or the `<video>`'s own `<track>` elements) and the picker reads them.

**Where they sit** is set in the panel. With a track on, a **Caption position** control (Top, Middle, Bottom) sets `CaptionStyle.position` for the window and the export alike. It starts at the `captionStyle` default's `position`, else bottom, on every open, and is readable as `captionPosition` on the picker.

**They look exactly as they will in the clip.** Reel draws the shown track's cues inside the crop window with the same painter the export burns them in with, laid out at the export's size and drawn scaled to the window. So what you see is the clip's captions in miniature: same font, box, wrapping and position. They redraw every frame while playing, on a seek, and when the window is resized. The picker never styles captions with CSS. Change the look with the `captionStyle` default, a [`CaptionStyle`](/reel/making-clips/captions#style) of overrides; the window and the export both use it, at the position chosen in the panel.

Where the cues come from depends on the track:

1. a track the player was given (a WebVTT file by URL, WebVTT text) or a `<video>`'s own `<track>`: its cues are read from the player's `<video>` text tracks, as `text:<n>` in reel's [`loadCaptionTrack`](/reel/making-clips/captions#the-sources-own-caption-tracks), so there is no second fetch;
2. an HLS stream's subtitle rendition, which the player finds in the playlist itself: the shown track is matched to the same rendition in reel's [`listCaptionTracks`](/reel/making-clips/captions#the-sources-own-caption-tracks), by name and then language, and only the WebVTT segments the timeline's window overlaps are fetched, once, for the preview and the export.

If the shown captions cannot be loaded (a rendition that will not load, say), the window shows none, the panel notes "These captions could not be loaded" and fires a non-fatal `reel-error` (`captions-unavailable`, its message saying why), and an export is made without them, the finished clip noting "The captions could not be loaded, so the clip was made without them."

## HLS and DASH sources

An HLS playlist URL works like a file. One opening reads the master playlist, and each media playlist it needs, once: the check, the filmstrip, the caption list, the captions and the export share a [playlist cache](/reel/making-clips/create-clip#reading-playlists-once) made when the picker opens and cleared when it closes. Playback is the player's business: Safari plays HLS natively and other browsers through hls.js, as the page's own player does. The **filmstrip and the export** read the stream with Mediabunny, from the [smallest variant that will do](/reel/making-clips/create-clip#hls-and-several-video-tracks), because frames played through MediaSource cannot be read back. The player's quality setting changes playback only; the clip is always cut from the source.

A DASH manifest plays (through dash.js, the player's other optional peer) but cannot be clipped: the picker reports [`'dash'`](/reel/reference/blockers) and keeps the export disabled.

## Sharing

**Share** calls `navigator.share({ files: [clip], title, text: caption, url: link })` where the browser can share files (Safari, Chrome on Android and ChromeOS, Edge on Windows). Targets that take text get the share caption with it. Elsewhere, and if sharing fails, it downloads the clip instead. Dismissing the share sheet does nothing.

**Copy caption with link** puts a ready-to-post caption on the clipboard, for pasting under the clip on TikTok, Instagram or WhatsApp, where a viewer can tap the link. By default it is the headline, a blank line and the deep link back to the moment:

```
Tides are rising faster than expected

https://www.acme.news/2026/10/tides-rising#ml-t=42,52
```

It uses `navigator.clipboard.writeText` and announces "Copied" through a polite live region. Where the clipboard is refused (no permission, an embedded frame, an older browser), the caption appears in a read-only field, focused and selected, ready to copy by hand. Change the text with the `shareCaption` default, a template or a function:

```ts
setPickerDefaults({ shareCaption: '{title} ({publisher})\n\n{url}' })
setPickerDefaults({ shareCaption: ({ title, url, start }) => `From ${Math.round(start)}s: ${title}\n${url}` })
```

## Your logo

Give the picker a logo and it brands every clip: stamped in a corner of the video and at the top of the end card. Setting `logo` also shows a **Logo on the clip** toggle beside the end-card toggle, with the stamp previewed where the export will put it.

```ts
setPickerDefaults({
  logo: 'https://cdn.acme.news/logo.svg', // same-origin, or cross-origin with CORS headers; SVG works
  stamp: { position: 'top-right' }, // true (default): on, top right; false: the toggle starts off
  displayUrl: 'acme.news/tides', // the address on the end card; defaults to the origin's, made readable
})
```

The default stamp placement keeps clear of the buttons TikTok, Reels and Shorts draw over a video; see [safe areas](/reel/making-clips/end-card#safe-areas).

## Keyboard and screen readers

The picker is an ordinary section of the page, not a modal: focus is not trapped and Escape does nothing. The player keeps its own keyboard shortcuts, so play, pause and sound are the player's.

| Control            | Role and keys                                                                                                                                                                                                                                                      |
| ------------------ | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| Position           | The playhead is `aria-hidden`; the time readout is plain text, not a live region, so it is not announced on every tick                                                                                                                                             |
| Start, end handles | `role="slider"` with `aria-valuemin`/`max`/`now` in seconds and `aria-valuetext` like `0:42.5`. Arrows move 0.5s, Shift+arrows and Page Up/Down 5s, Home/End jump as far as allowed. Handles never cross and keep the clip between the shortest and longest length |
| Crop window        | `role="slider"` labelled "Crop position", 0 to 100 with a spoken position. Arrows move the window (Shift moves it further), Home/End go to the edges; or drag it                                                                                                   |
| Copy caption       | A button; "Copied" (or the fallback hint) is announced through a polite live region, and the fallback field is a labelled read-only `<textarea>`                                                                                                                   |
| Player controls    | Buttons named by the labels: Play or Pause, Mute or Unmute, and `Captions: <track>` (`Captions: Off` with none). The time is plain text                                                                                                                            |
| Caption position   | A `<fieldset>` with a legend ("Caption position") and three radios: Top, Middle, Bottom. Shown only when a caption track is on                                                                                                                                     |
| Toggles            | Native checkboxes                                                                                                                                                                                                                                                  |
| Notes              | Non-fatal notes (thumbnails, captions) appear in a polite live region under the status line                                                                                                                                                                        |
| Progress           | `role="progressbar"` with `aria-valuenow`; status changes are announced through a polite live region                                                                                                                                                               |

## Theming

Every colour, the radius and the font of the panel, and the scrim over the picture, come from custom properties, set on the picker or any ancestor:

```css
ml-reel-picker,
.reel-picker {
  --reel-bg: #10241a;
  --reel-surface: #173426;
  --reel-fg: #f4f7f5;
  --reel-muted: #a9bdb2;
  --reel-accent: #e2a32e; /* also the crop window's border */
  --reel-accent-fg: #1b1405;
  --reel-range: rgba(226, 163, 46, 0.35);
  --reel-radius: 14px;
  --reel-focus: #ffd36b;
  --reel-font: system-ui, sans-serif;
  --reel-scrim: rgba(0, 0, 0, 0.55); /* what the crop window dims: the picture the clip leaves out */
  --reel-error: #ff9b8f;
  --reel-playhead: #fff; /* the line on the filmstrip */
  --reel-icon-size: 20px; /* the close button and the player controls */
  --reel-tile-placeholder: rgba(255, 255, 255, 0.06); /* filmstrip slots before their thumbnail */
}
```

The panel is `.reel-picker` and its parts are classes too (`.reel-timeline`, `.reel-transport`, `.reel-position`, `.reel-selection`, `.reel-handle`, `.reel-playhead`, `.reel-export-button`, `.reel-result`, `.reel-share`, `.reel-download`, `.reel-copy`, `.reel-notes`), since it has no shadow root. The player controls take `--reel-fg`, `--reel-muted` and `--reel-surface` (on hover), and the caption position pills `--reel-surface` and `--reel-accent`. The crop window (`.reel-crop`) and its overlay (`.reel-overlay`) are drawn inside the player's shell, outside the panel, so `--reel-accent` and `--reel-scrim` set on the picker reach them only if set on an ancestor of the player as well, such as `:root`.

### Icons

The close button uses the [sigil](/sigil/getting-started/introduction) library `mlv` that `@munsonlabs/video-player` registers, so the picker matches the player beside it and a page reskins both at once:

```ts
import { override } from '@munsonlabs/sigil'

override('close', '<svg viewBox="0 0 24 24">…</svg>', { library: 'mlv' }) // the player's and the picker's close icon
```

## Page-wide defaults

Labels, limits and branding live in a registry shared by every copy of reel on the page (on a well-known `globalThis` symbol, like [sigil's](/sigil/integrations/third-party-scripts)), so a script the app did not bundle can still reword or retune every picker:

```ts
import { setPickerDefaults } from '@munsonlabs/reel/vue' // or '@munsonlabs/reel/element'

setPickerDefaults({
  labels: { title: 'Make a short', export: 'Render' },
  length: 15, // the range it opens with
  longest: 60, // the longest clip allowed
  height: 720, // export at the crop's own 720 rows instead of the default 1080x1920 (smaller, softer)
  stallTimeout: 15, // seconds before a silent encoder fails the export
  logo: '/logo.svg', // the stamp and the end card
  stamp: { position: 'top-left' },
  displayUrl: 'example.com/interview',
  shareCaption: '{title}\n\n{url}',
  endCard: { cta: 'Read the full story at' },
  captionStyle: { margin: 0.28 }, // overrides on the caption look, e.g. higher up for TikTok or Reels
  watermark: { text: 'example.com' },
  filename: (title, start, end) => `example-${Math.round(start)}-${Math.round(end)}`,
})
```

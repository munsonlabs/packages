[`@munsonlabs/video-player`](/video-player/getting-started/introduction) takes one extra HUD button through its [`action` prop](/video-player/api/props#ui): a custom action is `{ icon, label, onClick }`, with `icon` as SVG markup. That is all a "Clip this" button needs.

The picker is built on the player and sits under it: the page's player is the preview, so a page that already has the player pays only for reel's own components. The player knows nothing about reel: the picker drives it through its public handle ([`setClipRange`](/video-player/features/clip-range), the caption state, `mediaElement` for the time per frame) and draws the crop window over its picture. The links back are plain [deep links](/video-player/features/deep-links).

## The recipe

::steps

### Ask whether this video can be clipped

Before showing the action, ask `canClip`. It reads only the file header and never throws. A YouTube or Vimeo source answers `'embed'`, an HLS stream played through hls.js answers `'mse'` for the `<video>` (pass the playlist URL instead, which reel reads directly), a DRM stream `'drm'`.

Given the playlist URL as the picker's `source`, it builds its filmstrip from the stream's lowest variant with Mediabunny; the player plays the stream (hls.js outside Safari, which a page that plays HLS already has), and the subtitle rendition the viewer has on is burned in.

```ts
const { canClip } = await import('@munsonlabs/reel') // late, so Mediabunny is not in the page bundle
const check = await canClip(src)
```

### Offer the action only when it works

```ts
const scissors =
  '<svg viewBox="0 0 24 24" fill="none" stroke="currentColor" stroke-width="2" aria-hidden="true"><circle cx="6" cy="6" r="3"/><circle cx="6" cy="18" r="3"/><path d="M20 4 8.12 15.88M14.47 14.48 20 20M8.12 8.12 12 12"/></svg>'

action.value = check.ok ? { icon: scissors, label: 'Clip this', onClick: openPicker } : null
reason.value = check.ok ? '' : check.message // show it in a tooltip or a help link if you like
```

The player has one action slot and no disabled state, so the honest choices are to hide the action (as here) or to keep it and let the picker explain the reason (it shows the same message and fires `reel-error`).

### Put the picker under the player, and open it on the scissors

Give the picker the player's handle (the `VideoPlayer` template ref) or, for `<ml-video-player>`, its id in `for`. The player's `deep-link` id goes in `origin.player`, so the clip's link comes back to this player. The scissors set `open`, and the picker pauses the player, takes its position as the moment and loops the range on it.

```vue
<VideoPlayer ref="player" :src="src" :action="action" deep-link="interview" />
<ReelPicker
  v-model:open="open"
  :player="player"
  :source="src"
  :origin="{ url: location.href, title: 'The interview', publisher: 'Example News', player: 'interview' }"
/>
```

```html
<ml-video-player id="interview" src="/video/interview.mp4" deep-link="interview"></ml-video-player>
<ml-reel-picker for="interview" src="/video/interview.mp4"></ml-reel-picker>
```

```ts
import '@munsonlabs/reel/element' // the core and Mediabunny load on show()

const picker = document.querySelector('ml-reel-picker')
picker.origin = { url: location.href, title: 'The interview', publisher: 'Example News', player: 'interview' }
const openPicker = () => picker.show() // the action's onClick
```

Inside the player's slot the picker needs neither `player` nor `for`: it finds the enclosing player, and renders in the player's own layer.

```vue
<VideoPlayer :src="src" :action="action" deep-link="interview">
  <ReelPicker v-model:open="open" :origin="origin" />
</VideoPlayer>
```

### Let links come back

Turn on [deep links](/video-player/features/deep-links) on the same player, with the id the origin names. A clip's metadata, the shared link and the copied caption all point at `#ml-t=start,end&ml-player=interview`, and that player opens there, scrolled into view with the range highlighted.

### Share from the page

The picker's own **Share** and **Copy caption with link** are usually enough. For a share button of your own, `reel-export` carries the file and the deep link, and `shareCaption` on the picker is the ready-to-post caption (the [`shareCaption` default](/reel/picker/picker#sharing), filled in): pass them to `navigator.share` as the picker does.

```ts
picker.addEventListener('reel-export', async (event) => {
  const { blob, link } = event.detail
  const file = new File([blob], 'interview.mp4', { type: blob.type })
  const data = { files: [file], text: picker.shareCaption, url: link ?? undefined }
  if (navigator.canShare?.(data)) await navigator.share(data)
})
```

## With the web component

`<ml-reel-picker>` and `<ml-video-player>` work the same way, with no framework on the page. Vue copies everything a player exposes onto its element, so the `<ml-video-player>` node _is_ the handle: `togglePlay()`, `isPlaying`, `setClipRange()`, `setControls()` and `mediaElement` live on the DOM element. `for` names that element by id; the picker looks it up, waits for the tag to be defined if it is not yet, and passes the element to its own controls as their `player`. Those are video-player's headless controls, and their buttons re-render when the element's state changes, because both packages share the page's one copy of Vue (the player is an external peer of reel's element build; two copies of Vue on a page would break that link, as it would for the player's own `<ml-*>` controls).

```html
<ml-video-player id="interview" src="/video/interview.mp4" deep-link="interview"></ml-video-player>
<ml-reel-picker for="interview"></ml-reel-picker>

<script type="module">
  import '@munsonlabs/video-player/element'
  import '@munsonlabs/reel/element'
  import { canClip } from '@munsonlabs/reel'

  const player = document.getElementById('interview')
  const picker = document.querySelector('ml-reel-picker')
  picker.origin = { url: location.href, title: 'The interview', publisher: 'Example News', player: 'interview' }

  const check = await canClip(player.getAttribute('src'))
  if (check.ok) player.action = { icon: scissors, label: 'Clip this', onClick: () => picker.show() } // scissors: the SVG string above

  picker.addEventListener('reel-export', ({ detail }) => console.log(detail.link))
</script>
```

Two differences from the Vue form. The picker cannot be nested inside `<ml-video-player>` without `for`: a Vue component finds the enclosing player through provide/inject, which does not cross from one custom element's app into another's. And properties that are objects (`origin`, `source` as a `File`, `endCard` as options) are set in JavaScript, as above; attributes carry the strings (`for`, `src`, `open`).

While the editor is open the picker calls `setControls(false)` on the player, so its HUD is out of the way under the crop window, and the panel's own controls stand in; `setControls(null)` on close gives the `controls` attribute back its say.

## All of it in Vue

```vue
<script setup lang="ts">
import { onMounted, ref, shallowRef } from 'vue'
import { VideoPlayer, type CustomAction, type PlayerHandle } from '@munsonlabs/video-player'
import { ReelPicker } from '@munsonlabs/reel/vue'
import '@munsonlabs/video-player/style'
import '@munsonlabs/reel/style'

const src = '/video/interview.mp4'
const player = ref<PlayerHandle>()
const action = shallowRef<CustomAction | null>(null)
const open = ref(false)

onMounted(async () => {
  const { canClip } = await import('@munsonlabs/reel')
  const check = await canClip(src)
  action.value = check.ok ? { icon: scissors, label: 'Clip this', onClick: () => (open.value = true) } : null // scissors: the SVG string above
})
</script>

<template>
  <VideoPlayer ref="player" :src="src" :action="action" deep-link="interview" />
  <ReelPicker
    v-model:open="open"
    :player="player"
    :source="src"
    :origin="{ url: 'https://example.com/interview', title: 'The interview', player: 'interview' }"
  />
</template>
```

The [reel demo app](https://github.com/munsonlabs/packages/tree/idea/reel/apps/demos/reel) is this recipe on an article page, with a `?source=` switch between an MP4 with English and French WebVTT caption files given to the player, the default, and two HLS streams, one with subtitle renditions.

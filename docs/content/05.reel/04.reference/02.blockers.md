Every way a source is refused is a code, not a stack trace. `canClip` resolves `{ ok: false, reason, message }` and never throws; `createClip` throws a `ClipError` with the same `reason`; the picker shows the message and fires `reel-error`.

| `reason`                | Source                                                                                     | Instead                                                                |
| ----------------------- | ------------------------------------------------------------------------------------------ | ---------------------------------------------------------------------- |
| `mse`                   | A `<video>` fed by MediaSource: hls.js, dash.js, Shaka                                     | Pass the HLS playlist URL; reel reads HLS directly                     |
| `dash`                  | A `.mpd` manifest                                                                          | A progressive MP4 or an HLS rendition of the same video                |
| `drm`                   | A `<video>` with `mediaKeys` (EME)                                                         | None: decoded frames of protected media are not readable, by design    |
| `media-stream`          | A `<video>` playing a `MediaStream` (camera, screen, WebRTC)                               | Record it first (`MediaRecorder`) and clip the recording               |
| `embed`                 | A YouTube, Vimeo, Dailymotion, Brightcove or JW Player page URL                            | None: the pixels live in someone else's iframe                         |
| `unreachable`           | A URL that cannot be fetched, most often a cross-origin file without CORS                  | Serve it with `Access-Control-Allow-Origin` and allow `Range` requests |
| `unsupported-container` | Bytes that are not MP4, MOV, WebM, MKV, MPEG-TS, HLS or another container Mediabunny reads |                                                                        |
| `no-video`              | No video track                                                                             |                                                                        |
| `undecodable-video`     | This browser cannot decode the video codec (also what encrypted tracks look like)          | Another rendition, e.g. H.264 rather than HEVC                         |
| `no-video-encoder`      | No H.264 encoder at the clip's size (clips are always H.264 in MP4)                        | A smaller `crop.height`                                                |
| `no-webcodecs`          | No WebCodecs or `OffscreenCanvas`, or not a secure context                                 | HTTPS, and a current browser                                           |

Captions that cannot be loaded are not a blocker: `createClip` makes the clip without them and warns `captions-unavailable` through `onWarning` ([see captions](/reel/making-clips/captions#caption-files-by-url)). Nor is audio this browser cannot write as AAC (a source with Opus audio in Firefox): the clip is silent and `onWarning` gets `audio-unavailable` ([see output](/reel/making-clips/create-clip#output)).

The picker adds three of its own: `no-player` (no player to clip, through `player`, `for` or the slot), `no-source` (the player's source cannot be read, a `blob:` URL from hls.js, and no `source` was given) and `export-failed` (anything unexpected during an export, with the browser's message). Its non-fatal reasons (`fatal: false`), where the picker carries on without something optional, are `logo-unavailable`, `thumbnails-unavailable`, `captions-unavailable` and `audio-unavailable`.

## Two things that look like blockers but are not

- **HLS.** A `.m3u8` URL clips fine: Mediabunny reads the playlist and only the segments the range needs, from the smallest variant that covers the output ([variants](/reel/making-clips/create-clip#hls-and-several-video-tracks)). It is the `<video>` element fed by hls.js that cannot be read, because its `src` is a `blob:` URL for a MediaSource.
- **Rotation.** Phone video stored landscape with a rotation matrix is handled; see [crop](/reel/making-clips/crop#rotated-video).
